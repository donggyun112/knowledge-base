# 개인 지식베이스 공개 설계

상태: 구현 전 검토용. GitHub 저장소 생성·업로드·배포는 아직 수행하지 않음.

## 목적과 합의된 범위

사용자의 Obsidian 지식을 웹에서도 읽고 검색하고 링크로 탐색한다. 별도 브랜드, 소개용 랜딩 페이지, 제품 기능은 만들지 않는다. 원본은 `/Users/dongkseo/Documents/Obsidian Vault/research`이며 현재 Markdown 노트 84개, 분류 폴더 5개와 인덱스·읽기 가이드가 있다. 웹으로 내보낼 때만 별도 사본을 만든다.

## 구현 선택

Quartz의 검색·백링크·그래프·Obsidian 문법 지원을 재사용한다. 기존 Inception 사이트의 Cytoscape 데이터와 본문을 따로 작성하는 구조는 가져오지 않는다. 직접 정적 생성기를 새로 만드는 방식도 선택하지 않는다.

Quartz 공식 사이트는 현재 v5를 소개하지만 GitHub Releases의 latest 응답은 오래된 v4.0.8이다. 구현 시작 시 실제 소스의 버전·설치 지침을 대조하고 검증한 커밋과 잠금 파일을 고정한다. 릴리스 API의 latest 값만으로 버전을 고르지 않는다.

호스팅은 사용자가 지정한 GitHub Pages를 유지한다. 새로운 전용 저장소의 작업 이름은 `knowledge-base`, 예상 주소는 `https://donggyun112.github.io/knowledge-base/`다. 기존 Inception 사이트는 별도 프로젝트로 유지한다. Sites 전용 호스팅으로 이동하지 않는다.

## 화면

- 제목은 `Donggyun의 지식베이스`. 별도 홍보 문구 없이 기존 분류와 읽기 가이드·전체 인덱스로 바로 접근한다.
- 폴더 탐색과 한국어 본문, 전체 검색, 목차, 백링크, 현재 노트의 관계 그래프와 전체 그래프를 제공한다.
- 코드 블록·표·수식·Mermaid·callout·별칭과 앵커가 붙은 위키링크를 기존 엔진으로 렌더링한다.
- 원문 출처, 조사일, 미확인 항목을 보존한다. 조사일을 최신 검증일처럼 바꾸지 않는다.
- 모바일에서는 본문을 우선하고 탐색 기능은 접어 사용할 수 있게 한다. 프레임워크 기본 접근성·키보드 동작을 유지한다.

## 공개본 생성과 갱신

`research`만 읽는 내보내기 명령을 제공한다. 입력 폴더를 수정하지 않고 사이트 저장소의 공개 콘텐츠만 갱신한다. 금지된 경로를 따라가지 않도록 입력 범위를 확인하고 심볼릭 링크는 내보내지 않는다. 삭제된 원본은 다음 내보내기에서 공개 사본에서도 제거한다.

첫 공개본에서는 `non-research-links.md`와 `speechify-library.md`를 제외한다. 노트의 `우리 맥락` 등 개인 회사에 적용하는 아이디어 절은 공개 사본에서 제외하고, 연구 내용·일반적 한계·출처는 보존한다. 이는 원문 수정이나 재집필이 아니라 공개 범위를 줄이는 변환이다. 특정 회사에 관한 공개 출처를 요약한 연구 내용은 단순 키워드만으로 제거하지 않는다.

개인 적용 절의 변형 제목과 남은 내부 정보는 실제 내보내기 때 확인하고, 제외 목록과 변환 내역을 로컬에서 검토할 수 있게 한다. 원본 전체나 원본이 포함된 Git 이력을 공개 저장소에 넣은 뒤 나중에 삭제하는 방식을 쓰지 않는다.

기존 INDEX·READING-GUIDE에 제외된 문서로 향하는 링크가 있으면 공개본에서 해당 항목을 제외한다. 나머지 실제 링크는 보존한다. 코드 예시 안의 `[[...]]`는 그래프 연결로 잘못 취급하지 않는다. 진짜 미해결 링크는 따로 보고하며 존재하지 않는 문서를 만들어 채우지 않는다.

일반 갱신 흐름은 `Obsidian 수정 → 로컬 내보내기·빌드 → Git 변경 검토·push → GitHub Actions 배포`다. 로컬 Obsidian 파일을 바꾼 것만으로 원격 사이트가 자동 갱신된다고 설명하지 않는다. 무인 감시 프로세스나 예약 업로드는 이번 범위에 없다.

## 파일과 검증 범위

- Quartz 설정·레이아웃·스타일과 배포 workflow: 필요한 최소 설정만 변경한다.
- 콘텐츠 내보내기: 범위 제한, 제외·절 제거, 삭제 반영과 원본 불변을 검증하는 작은 테스트를 둔다.
- 공개 노트 사본: 원문·링크·조사일·제외 결과를 대조한다.
- 빌드: 한글 경로와 GitHub Pages의 `/knowledge-base/` 하위 경로에서 HTML·검색 인덱스·그래프 데이터가 일치하는지 확인한다.
- 브라우저: 실제 검색, 노트 이동, 백링크, 그래프 노드 클릭, 다크 모드와 좁은 화면을 확인한다.
- 배포: 공개할 파일과 로컬 미리보기를 구체적으로 확인한 뒤 GitHub Actions 결과와 실제 URL 응답을 확인한다. 실패하면 로컬 결과와 배포 실패를 구분해 보고한다.

## 완료 기준

Obsidian 원본을 유지하면서 공개된 노트를 본문·검색·백링크·그래프로 탐색할 수 있다. 한 노트를 수정하고 다시 내보내면 본문과 연결 정보가 같이 반영된다. 공개 제외 문서는 HTML뿐 아니라 검색·그래프·업로드 파일과 Git 이력에도 들어가지 않는다. 실제 배포 확인 전에는 공개 완료라고 주장하지 않는다.

## 하지 않는 일

RAG, 임베딩, LLM 검색, 별도 DB·서버·로그인, 분석 추적, 새로운 도메인 구매, 전체 Vault 공개, 기존 노트 사실관계의 재조사는 포함하지 않는다.
