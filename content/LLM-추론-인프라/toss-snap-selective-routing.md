# 토스 SNAP — 소형 모델이 맡을 요청을 검증으로 고르기

토스는 동일 상품 판별처럼 입력과 출력이 명확한 작업에서 소형 모델을 먼저 호출했다. 검증 데이터에서 정한 임계값을 넘으면 그 결과를 쓰고, 나머지는 기존 LLM에 다시 요청한다. 비교 기준은 소형 모델이 모든 요청을 얼마나 잘 처리하는지가 아니라, **요구한 일치율에서 얼마나 많은 요청을 대신 처리할 수 있는가**다.

- **발행일**: 2026-10-27
- **수집·검증일**: 2026-11-23 KST
- **검증 범위**: 공개 운영 사례의 정적 검토. 데이터 접근·재현·모델 호출은 하지 않았다.

## 평가와 운영에서 확인한 것

토스는 시스템 프롬프트 앞부분의 해시로 비슷한 요청을 작업별로 묶고, 추정 비용이 크면서 기존 응답에서 학습용 라벨을 안정적으로 추출할 수 있는 작업을 선별했다. 모델과 채택 임계값은 검증 데이터에서 함께 골랐다.

| 구분 | 토스가 보고한 결과 |
| --- | --- |
| 오프라인 | 목표 일치율 99.9%에서 검증 요청 100,648건 중 34,963건 채택(34.74%). 채택 결과 34건이 기존 LLM 판단과 달라, 일치율은 99.9028%. 목표를 99%로 낮추면 채택률 51.59%, 95%에서는 72.35%. |
| 운영 | 첫 배포 후 약 6일간 소형 모델이 처리한 비율은 일별 33~37%. 이 기간 줄어든 기존 LLM 사용량은 입력 토큰 약 76억 개, 출력 약 4,520만 개. |
| 부하 시험 | L4 GPU 한 장에서 소형 모델 경로의 실제 초당 1,203건 구간은 클라이언트 응답시간 p50 9.02ms, p99 15.23ms. 운영 전체나 폴백 경로의 지연은 아니다. |

## 적용할 때 남는 질문

여기서 선택적 정확도는 **기존 LLM과의 일치율**이다. 사람이 검수한 정답률이나 독립 테스트셋 성적, 운영 정확도로 읽으면 안 된다. 운영에서 소형 모델이 맡은 요청 비중과 실제 줄어든 순비용도 다르다. 폴백 요청은 두 모델을 모두 호출하므로, 손익분기점은 피한 기존 LLM 비용이 전체 소형 모델 호출과 추가 운영비를 넘는지로 판단해야 한다.

작게 검증한다면 임계값을 고른 데이터와 별도로 사람 검수 표본을 두고, 전체 기존 LLM 경로와 소형 모델 우선 경로를 비교한다. 채택률·채택 구간의 실제 오류율·순비용·폴백 포함 종단 간 p95를 따로 본다. 고가 요청이 주로 폴백에 남는지도 확인하면, 채택률만 보고 절감액을 과대 추정하는 일을 피할 수 있다.
