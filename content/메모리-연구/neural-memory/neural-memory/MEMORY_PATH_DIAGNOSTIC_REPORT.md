# 메모리 경로 원인 분리 실험 — 2026-09-26

## 결론

이 실험은 실패를 ‘기억이 안 된다’는 한 문장으로 끝내지 않고, **읽기 통로 자체가 정보를 전달할 수 있는지**부터 확인한다. residual 읽기란 기억에서 얻은 값을 언어모델의 마지막 내부 표현에 더해 예측을 바꾸는 방식이다.

같은 읽기 구조에 정확한 과거 근거를 주어 학습한 오라클은 100%를 맞혔다. 모든 과거 토큰을 직접 처리하며 쓰는 순환 모델도 지연 회상에서 약 90%를 맞혔다. 오라클 사전학습 없이 쓰기·읽기를 처음부터 함께 배우면 seed 7은 93.2%, seed 17은 87.5%였다. 적어도 이 구조로 정보를 되돌려 쓰는 것 자체는 가능하다.

그러나 **이것으로 기존 MSC 모델의 실패 원인을 확정한 것은 아니다.** 여기서는 단일 사실을 기억하는 인공 양성 대조를 썼다. 양성 대조는 기억할 정보가 분명한 쉬운 과제로, 경로가 작동할 여지가 있는지 확인하는 시험이다.

직접 확인한 문제는 이 과제에서 16토큰마다 한 번 입력하면 성능이 떨어진다는 점, 짧은 잡담만 학습하면 긴 잡담에서 불안정하다는 점이다. 기존의 ‘다음 발화 예측’ 목표가 문제라는 설명도 유력한 가설로 남지만, 이번 실험이 그 원인을 직접 분리한 것은 아니다.

## 실험 통제

- **모델과 기기:** SmolLM2-135M-Instruct와 출력 헤드를 모두 고정하고 float32, Apple MPS GPU에서 실행했다.
- **읽기 통로 통제:** 모든 메모리 조건은 기존 `SelectiveTokenMemory.read`와 같은 최종 hidden residual 경로를 쓴다. 기존 MSC 체크포인트를 가져온 것이 아니라 진단용 가중치를 새로 학습했다.
- **과제:** 과거에 `Me: My secret word is apple.`처럼 한 사실을 말하고, 무관한 잡담 뒤에 `What was your secret word?`를 묻는다. 정답은 apple/moon/glass/dog/river/chair/green/stone의 8개다. 실제 토크나이저에서 과거 사실의 단어와 정답이 같은 단일 토큰인지 검사한다.
- **질문만 보고 맞히는 것을 막는 방법:** 독립 잡담 블록마다 정답 단어만 다른 8개 사례를 만든다. 같은 블록의 질문, 에피소드 표식, 잡담, 사실 위치는 같다. 따라서 질문 형식만으로 정답을 구별할 수 없다.
- **자료 분할과 거리:** train 32블록/256사례, valid 8블록/64사례, test 24블록/192사례다. 학습·검증 잡담은 2·4턴, 시험 잡담은 4·8·16턴이다. 분할 사이에 블록 ID는 겹치지 않는다.
- **기억 크기와 학습:** 메모리 폭은 128, 잠재 슬롯은 8개다. 순환 쓰기는 사례마다 0 상태에서 시작하며 외부 검색이나 key/value 레코드를 추가하지 않는다. 손실은 8개 후보만 구별하는 분류가 아니라 **고정 LM 전체 어휘에서 정답 토큰을 맞히는 cross entropy**다.
- **오라클이 받는 특권:** 정답 단어가 실제로 등장한 **과거 토큰 위치**의 LM 상태를 전달한다. 미래 정답을 미리 주는 것은 아니지만 근거 위치를 안다는 특권은 있다. 단일 사실을 모든 슬롯에 반복하므로 여러 사실 중 질의에 맞는 것을 선택하는 능력은 검증하지 않는다.
- **상태 교환과 빈 상태:** 같은 잡담 블록 안에서 상태를 순환 교환해 donor, 즉 기억 제공자의 정답이 반드시 다르게 만든다. 답이 donor 단어로 바뀌는지도 별도로 잰다. 빈 상태는 엄격히 zero residual이다. 빈 상태의 8지선다 정확도는 12.5%, 전체 어휘 top-1 정확도는 0%다.
- **불확실성:** NLL 차이의 신뢰구간은 서로 연관된 8개 사례 대신 독립 잡담 블록을 재표집해 구한다. 다만 같은 test에 여러 대조를 수행했으므로 결과는 탐색적이다.

표에서 scratch는 오라클 사전학습 없이 시작했다는 뜻이다. 오라클 초기화 모델은 먼저 오라클 400스텝을 거친 뒤 쓰기를 400스텝 더 학습했다. 따라서 scratch 400스텝과 학습량이 같다고 읽으면 안 된다. 입력 간격의 직접 비교에서는 scratch끼리 같은 seed·데이터·스텝을 맞췄다.

### 노이즈와 학습량

| seed 7, 사전학습 없음 | 잡담 4턴 | 잡담 8턴 | 잡담 16턴 |
| --- | ---: | ---: | ---: |
| 모든 토큰, 400스텝 | 100% | 98.44% | 81.25% |
| 모든 토큰, 2000스텝 | 100% | 93.75% | 57.81% |
| 16토큰 간격, 400스텝 | 12.50% | 12.50% | 12.50% |
| 16토큰 간격, 2000스텝 | 26.56% | 14.06% | 12.50% |

2000스텝 실행도 마지막 상태를 무조건 사용하지 않고 valid NLL로 체크포인트를 골랐다. 짧은 잡담의 검증 손실은 더 낮아졌는데도 긴 잡담 시험에서는 성능이 떨어졌다. **학습을 더 오래 하는 것만으로 잡담에 대한 내성이 좋아지지는 않았다.**

16토큰 간격으로 바꾸면 두 가지가 동시에 달라진다. writer가 관측하는 지점 수가 줄고, 상태를 갱신하는 횟수도 줄어든다. 따라서 성능 저하가 관측 정보의 손실 때문인지 갱신 과정 때문인지 하나로 확정할 수 없다. 정보가 반드시 사라졌다고도 단정하지 않는다.

또 각 토큰의 LM 상태에는 앞선 문맥이 이미 들어 있다. 모든 토큰을 입력한 조건이 잘됐다고 해서 writer가 원시 토큰 기억을 혼자 학습했다고 주장할 수도 없다.

과거 전체를 원래 LM의 프롬프트에 넣은 조건은 제한된 8지선다에서는 100%였지만, 전체 어휘에서 가장 높은 점수를 받은 토큰(top-1)은 정답률 0%였다. 후보 여덟 개 안에서는 정답을 선호하더라도, 전체 어휘에서는 다른 토큰을 먼저 내놓을 수 있다는 뜻이다. 답 형식이 LM의 자연스러운 다음 토큰과 맞지 않았을 가능성이 있으며, 이 조건에서 자유 생성까지 성공했다고 보지 않는다.

## 기존 실패에 대한 판단 수정

1. 읽기 통로가 원천적으로 불가능하다는 해석은 지지되지 않는다. 그러나 단일 단어 결과로 여러 사실·자연어 문장·기존 체크포인트의 읽기 능력을 보증할 수는 없다.
2. 쓰기·읽기를 함께 학습하는 것 자체도 불가능하지 않다. 사전학습 없는 모든 토큰 모델도 두 seed에서 기억을 사용했다.
3. 16토큰 간격을 계산 최적화로 사용한 이전 실험은 안전한 근사라는 보장이 없었다. 같은 과제·seed에서 실제로 성능이 크게 떨어졌다. 실제 MSC에서 이 변경의 효과는 별도 실험이 필요하다.
4. 빈 상태 대비 큰 NLL 개선만으로 기억 성공을 선언할 수 없다는 점이 다시 확인됐다. 16토큰 scratch 400스텝 모델은 빈 상태 NLL 16.97을 자기 상태 2.44로 낮췄지만, 자기와 교환 상태 모두 12.5%였다. 단어 집합의 공통 사전확률만 익혀도 그런 개선이 가능하다.
5. 기존 목적함수와 이번 과제는 다르다. 따라서 원래 MSC 목적함수가 실패의 유일한 원인이라는 인과 결론은 아직 없다.

## 다음 검증 순서

다음에는 단일 사실을 넘어서 여러 사실, 정정된 사실, 과거를 꺼낼 필요가 없는 질문을 넣는다. 학습 중의 잡담 길이도 다양하게 만든 뒤, 실제 사람 대화의 사실을 나중에 묻는 과제로 옮긴다.

각 단계마다 자기/빈/교환 상태를 비교한다. 또한 필요 없는 기억을 억제하는지, 사실이 바뀐 뒤 최신 정보를 회상하는지를 따로 검사한다.

이 진단은 RMT/TTT/Titans 재현을 대체하지 않는다. 논문 충실도 비교와 실제 대화 실험은 별도로 남아 있다. 자동 저장 판단·반환 타이밍·장기 다중 사실 메모리도 아직 검증되지 않았다.
