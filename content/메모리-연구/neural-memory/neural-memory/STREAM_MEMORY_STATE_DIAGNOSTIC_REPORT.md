# 사람 대화 기억 상태의 정보·읽기 분리 진단 — 2026-09-28

## 결론

이 보고서는 개인별 기억이 잘 쓰이지 않는 이유를 두 단계로 나눠 묻는다. **과거 정보가 상태에 남지 않는가, 아니면 남은 정보를 읽어서 출력에 쓰지 못하는가?**

현재 모델은 빈 상태보다 자기 과거 상태에서 미래 발화를 잘 예측한다. 하지만 다른 사람의 과거 상태를 넣어도 예측은 거의 같다. 같은 사례에서 원문을 직접 읽는 고정 언어모델은 사람별 차이를 보인다. 또 별도의 선형 판독기는 순환 상태에서 과거 단어 정보를 일부 읽어 냈지만, 기억 학습 전후의 차이는 작았다.

따라서 **상태에 정보가 전혀 없다고 단정할 수는 없다. 다만 현재 학습이 유용한 개인별 내용을 상태에 더 담고 미래 예측에 활용하게 만들었다는 증거도 없다.** 아래에서는 원문 비교, 상태 판독, 학습 조건 변경을 차례로 기록한다.

## 원문 과거와 순환 기억의 사례별 비교

먼저 ‘이 대화의 과거 원문에 쓸 만한 정보가 있는가’와 ‘순환 상태로 넘겼을 때 그 정보가 쓰이는가’를 같은 사례에서 비교했다. 기존 [[메모리-연구/neural-memory/neural-memory/STREAM_MEMORY_READ_ADAPTER_REPORT|토큰 조건부 읽기 모델]]의 선택 체크포인트를 MSC test 96개에 다시 평가하고, 원문 직접 읽기의 점수도 사례별로 저장했다.

NLL은 정답 예측 손실로 낮을수록 좋다. 표의 `타인−자기`가 양수면 자기 과거가 타인의 과거보다 유리하다는 뜻이다. 다만 두 경로의 입력 구조가 다르므로 원문 점수를 순환 모델이 그대로 달성할 수 있는 성능이라고 보지는 않는다.

| 경로 | test `타인−자기` NLL [95% 구간] |
| --- | ---: |
| 고정 언어모델, 원문 과거 직접 읽기 | +0.0777 [0.0443, 0.1115] |
| 고정 언어모델 + 순환 기억 | +0.00421 [0.00047, 0.00768] |

원문을 타인의 것으로 바꿨을 때 가장 크게 나빠진 24개 사례를 따로 보면, 원문 경로의 평균 효과는 +0.291이었다. 같은 사례에서 순환 기억의 효과는 +0.00082뿐이었다. 원문에서 과거가 중요했던 사례가 순환 기억에서도 유리한지 보는 전체 96개의 피어슨 상관은 −0.186이었다.

이 24개는 test 결과를 본 뒤 고른 사례다. 어디에서 차이가 나는지 살피는 탐색적 분석이며, 새 자료에서도 같은 효과가 날 것이라는 일반화 통계로 사용하지 않는다.

## 상태 내용 판독기

다음에는 모델이 출력에 쓰지 못하더라도 상태 안에 과거 정보가 남아 있는지 직접 읽어 봤다. 진단 코드 (`diagnose_stream_memory_state.py`; 원 저장소의 파일 참조)는 기억 모델 가중치를 고정하고, 상태만 보고 특정 토큰이 과거에 등장했는지 맞히는 **별도의 선형 ridge 판독기**를 학습한다. 이는 상태를 간단한 가중합으로 읽는 검사이며 본 모델의 기억 학습과는 별개다.

검사할 토큰은 train 512개 과거에서만 고른다. 판독기의 규제 강도는 valid 96개로 선택하고 test 96개에서 AUC를 잰다. AUC는 등장한 경우와 등장하지 않은 경우를 구분하는 능력을 보는 지표다. 일반 알파벳 토큰 64개와, 길이 5자 이상이며 영어 불용어를 제외한 내용 토큰 64개를 따로 검사했다. train 라벨을 무작위로 섞은 대조도 같은 절차로 수행했다. 이 라벨들은 본 기억 모델의 학습에 사용하지 않았다.

| 상태 | 일반 토큰 test macro AUC | 내용 토큰 test macro AUC |
| --- | ---: | ---: |
| 학습 전 writer | 0.538 | 0.586 |
| 기존 600스텝 기억 모델 | 0.541 | 0.587 |
| 아래 100스텝 보조 손실 모델 | 0.537 | 0.560 |
| train 라벨 섞기 대조 (기존/보조) | 0.498 / 0.498 | 0.472 / 0.505 |

학습 전 상태에서도 내용 토큰을 읽을 신호가 있었으므로 ‘상태가 비어 있다’는 해석은 맞지 않는다. 그러나 기존 600스텝 학습 뒤에도 이 신호는 거의 늘지 않았고, 아래 100스텝 후보도 개선하지 못했다.

이 검사가 묻는 것은 단어의 등장 여부뿐이다. 정확한 개인 사실, 정정, 필요한 때의 기억 반환을 재는 시험은 아니다. 간단한 선형 판독기가 잘 못 읽었다고 복잡한 비선형 방식으로도 정보가 없다고 증명할 수는 없다. 두 학습 모델의 스텝 예산도 다르므로 표만으로 직접 우열을 정하지 않는다.

## 구간 경계 자기지도 보조 손실 파일럿

기존 학습은 과거를 계속 읽지만, 학습 신호는 **마지막 세션의 한 발화**에서만 받는다. 신호가 너무 늦고 드물게 도착하는지 확인하려고 `--history-aux-weight` 옵션을 추가했다.

두 번째 이후 과거 구간이 시작될 때마다 실제 다음 토큰을 최대 32개 예측하게 한다. 같은 토큰을 자기 이전 상태와 타인 이전 상태로 각각 예측해 CE와 기존 자기/타인 대조 손실을 계산한다. 과거 중간에도 저장의 유용성을 배울 기회를 주는 방식이다. 수작업 중요도·기억 텍스트 라벨은 쓰지 않는다. 본 모델 기본값은 0(꺼짐)이며, 학습 후에도 빈 상태 예측과 고정 언어모델 경로를 유지한다.

처음 1스텝 점검에서는 구간 경계 손실이 마지막 답변 손실보다 컸다. 가중치 0.5로는 검증 NLL이 크게 악화됐다. 그래서 0.05로 낮춰 seed 29, MSC train 512·valid/test 각 96개, Apple MPS에서 100스텝 파일럿을 했다.

비교 대상은 기존 600스텝 실험의 **100스텝 시점**이다. 같은 검증 사례와 목적을 놓고 중간 손실 추가의 효과를 본다.

| 100스텝 검증 | `빈−자기` | `타인−자기` [95% 구간] |
| --- | ---: | ---: |
| 기존 학습 | +0.06257 | −0.00018 [−0.00412, 0.00404] |
| 구간 경계 보조 손실 0.05 | +0.06311 | +0.00124 [−0.01105, 0.01165] |

보조 손실 후보를 선택한 뒤 test에서 확인한 값은 `빈−자기` +0.06382, `타인−자기` −0.00071 [−0.00796, 0.00601]이었다. 빈 기억보다는 나았지만 타인 기억과의 구별은 생기지 않았다.

valid/test 모두 사전 개인별 기억 기준, 즉 `빈−자기`와 `타인−자기`가 각각 최소 +0.02이고 신뢰구간 하한이 양수여야 한다는 기준을 통과하지 못했다. 상태 판독도 좋아지지 않아 이 보조 손실을 600스텝으로 늘리는 것은 보류한다. 그렇다고 100스텝 결과만으로 더 긴 학습의 가능성까지 배제하지는 않는다.

전체 Python 테스트 **730개 통과**(기존 경고 1개). 파일럿 `.json`/`.pt`, 원문 사례별 감사 자료, 두 종류의 상태 판독 JSON은 `local-data/stream-rmt-human-read-history-aux-100-seed29*`, `local-data/stream-rmt-human-read-residual-contrastive-600-test-raw-audit.json`, `local-data/stream-rmt-human-read-*-probe-seed29.json`에 보존했다. MSC test는 프로젝트에서 이미 반복 확인한 탐색적 자료이며, 여전히 기억 텍스트/`NO_MEMORY`와 자동 반환 시점은 구현·검증되지 않았다.

## 후속 원인 분해: 공통 상태의 지름길

빈 상태보다 낫다는 이득이 개인 내용 없이도 나오는지 직접 검사했다. 같은 checkpoint로 MSC valid 96개 과거 상태의 평균을 만든 뒤, test 96개 모두에게 그 **하나의 공통 상태**를 넣었다.

test 평균 NLL은 자기 2.9809, 평균 상태 2.9833, 다른 사람 2.9851, 빈 상태 3.0682였다. 평균 상태와 자기 상태의 차이는 +0.00241 [−0.00026, 0.00499]뿐이었다. 한 사람의 기억 대신 공통 평균을 넣어도 빈 상태 대비 자기 상태 이득의 약 97%가 재현된 것이다.

관측 표식만 켜고 수치는 0인 상태는 NLL 3.4121로 오히려 나빴다. 따라서 단순히 `observed` 스위치가 켜진 효과만은 아니다.

그 공통 이득이 새 읽기 모듈에서 나오는지도 확인했다. 가중치는 그대로 두고 추론 중 잔차 읽기만 껐다. 자기/타인/평균 상태의 NLL은 각각 3.0451/3.0508/3.0477이 됐다.

읽기를 켰을 때의 개선은 각각 +0.0642/+0.0657/+0.0643으로 거의 같았다. 따라서 새 통로가 만든 큰 이득은 **개인별 내용을 골라 읽는 효과보다 공통 상태에 대한 보정**으로 설명된다. 첫 정답 토큰의 타인−자기 차이도 +0.0207이었지만 95% 구간 [−0.0028, 0.0410]이어서 불확실했다.

혹시 자기 과거가 더 길어서 원문 직접 읽기가 유리했던 것은 아닐까? 길이가 같은 test 67개에서도 자기/타인 차이는 +0.0554였다. 길이만으로 원문 효과를 설명할 수는 없다.

더 좁혀 보기 위해 과거의 첫 256토큰만 다른 사람 것으로 바꾸고, 나머지 길이와 최근 토큰을 유지했다. 93개 사례에서 원문 읽기는 +0.0476 [0.0234, 0.0719]만큼 나빠졌지만, 순환 기억은 +0.00441 [0.00075, 0.00805]만 변했다. 반대로 최근 구간만 바꾸면 원문 −0.00106 [−0.0167, 0.0156], 순환 기억 −0.00003 [−0.00015, 0.00008]로 거의 바뀌지 않았다.

이 과제에서 활용할 만한 과거 차이가 주로 첫 구간에 있다는 진단이다. 다만 대화를 이어 붙이면 자연스러움도 바뀌므로 순수하게 개인 사실만 바꾼 효과라고 단정하지 않는다.

두 번째 과거 구간의 갱신 gate 평균은 0.038로 작았다. 전체 과거를 본 상태와 첫 구간만 본 상태의 코사인 유사도도 0.991이었다. 실제로 첫 구간만 썼을 때 점수 차이는 −0.00106 [−0.00307, 0.00070]으로, 최근 구간은 현재 평가에 기여하지 않았다.

하지만 최근 구간을 바꿔도 원문 직접 읽기부터 거의 변하지 않았다. 그러므로 **gate가 작아서 새 정보를 쓰지 못했다는 설명만을 주원인으로 지목할 수 없다.** 이 과제에서 최근 정보 자체가 별로 필요 없었을 가능성을 함께 봐야 한다.

학습 자료를 실제 얼마나 봤는지도 확인했다. 600스텝 동안 train 512개 중 선택된 대화는 355개뿐이었다. 감사한 train 96개를 노출 0/1/2/3회 이상으로 나누면 타인−자기 차이는 각각 −0.0023/+0.0029/+0.0088/+0.0134였다.

원문 직접 읽기 효과를 공변량으로 넣고 분석했을 때 노출 횟수의 기울기는 약 +0.00537 nats/회, 사후 permutation p≈0.0032였다. 더 자주 본 대화에서 개인별 효과가 큰 관계는 보인다. 그러나 노출된 70개만 보아도 평균 +0.0063으로 합격 기준 +0.02에 못 미쳤고, 이 관계가 미사용 대화로 옮겨갈지는 별개다.

CE만 학습한 이전 모델의 200스텝 선택 상태도 163/512개에만 노출됐다. 본 사례의 타인−자기는 +0.0151, 못 본 사례는 거의 0이었다. 반복 노출에 기대는 현상은 대조 손실에만 생긴 문제는 아니다.

**현재 직접 확인한 실패 모습:** 상태가 완전히 빈 것은 아니다. 하지만 예측 이득 대부분은 사람 사이에서 바꿔 넣어도 되는 공통 상태에서 나온다. 원문 기준으로 첫 과거 구간에는 유용한 차이가 있는데, 상태→읽기→출력을 거치면 그 차이가 약 10분의 1로 줄어든다.

정보가 쓰는 도중 사라졌는지, 남아 있지만 읽을 때 무시되는지의 비율은 아직 분리하지 못했다. 고정 writer, 마지막 답변 한 개에 집중된 손실, 낮은 사례당 노출은 가능한 요인이다. 어느 하나를 단독 원인으로 확정하지 않는다.

후속 개입 원자료: `local-data/stream-rmt-human-read-residual-mechanism-first-seed29.json`, `local-data/stream-rmt-human-read-residual-writer-two-splice-seed29.json`, `local-data/stream-rmt-human-read-residual-train96-raw-audit.json`, `local-data/stream-rmt-human-frozen-ce-train96-raw-audit.json`. 진단 코드는 공통 상태 개입 (`diagnose_stream_memory_mechanism.py`; 원 저장소의 파일 참조), 쓰기 구간 치환 (`diagnose_stream_memory_writer.py`; 원 저장소의 파일 참조), 학습 노출 분석 (`diagnose_stream_memory_sampling.py`; 원 저장소의 파일 참조)에 있다. 모두 기존 체크포인트의 파라미터를 바꾸지 않았다.

## 후속 원인 분해: 빠진 학습 대화를 전부 보게 하면 해결되는가

앞선 분석에서는 학습 대화 512개 중 157개를 한 번도 보지 못했다. 이것만 바로잡으면 개인별 기억이 생기는지 확인하려고 학습 코드 (`train_stream_memory_human.py`; 원 저장소의 파일 참조)에 `--sampling epochs`를 추가했다.

기존 기본값은 한 번 뽑은 대화를 다시 뽑을 수 있는 복원 추첨이다. 새 옵션에서는 512개를 무작위 순서로 한 번씩 모두 본 뒤 다음 epoch로 간다. seed 29, 같은 train/valid/test 512/96/96개, 600스텝을 사용하고 손실·모델·학습률·평가 간격은 고정했다.

새 실험은 600스텝 체크포인트가 선택돼 **512개 대화를 모두 본 상태**다. 기존 600스텝 선택 모델이 본 대화는 355개였다.

| 선택 상태, MSC test 96개 | 본 train 대화 | `빈−자기` NLL | `타인−자기` NLL [95% 구간] |
| --- | ---: | ---: | ---: |
| 기존 복원 추첨 | 355/512 | +0.08727 | +0.00421 [+0.00044, +0.00768] |
| 전체 순회 후 재섞기 | 512/512 | +0.09181 | −0.00180 [−0.00384, +0.00017] |

모든 학습 대화를 본 새 모델도 빈 상태보다 자기 상태에서 예측이 좋았다. 그러나 다른 사람 상태로 바꿔 넣으면 평균적으로 오히려 조금 좋아졌다. valid/test 모두 `빈−자기`와 `타인−자기` 각각 +0.02 이상, 95% 구간 하한 양수라는 사전 기준을 통과하지 못했다.

독립적인 사례별 감사 평가 (`eval_stream_memory_human.py`; 원 저장소의 파일 참조)에서 같은 96개 대화와 점수가 재현됐고 체크포인트 파라미터는 변하지 않았다. 같은 test에서 원문 과거를 직접 읽는 고정 언어모델의 교환 효과는 +0.07766이었다.

새 모델에도 공통 상태 개입 (`diagnose_stream_memory_mechanism.py`; 원 저장소의 파일 참조)을 반복했다. test 평균 NLL은 빈 상태 3.06818, 자기 2.97637, 타인 2.97457, **valid 96개로 만든 공통 평균 상태 2.97529**였다. 공통 상태가 오히려 자기보다 약간 좋아, 빈 상태 대비 자기 상태 이득의 100% 이상을 재현했다.

잔차 읽기를 끄면 자기/타인/공통 상태 NLL이 함께 3.03286/3.03155/3.03181로 나빠졌다. 새 읽기 경로의 약 0.056 NLL 개선도 개인별 선택 읽기보다 공통 보정이라는 해석이다. 자기/타인 상태의 코사인 평균은 0.99476이었다. 유사도가 높다는 사실만으로 내용이 없다고 증명하는 것은 아니다.

과거 내용 토큰 64개의 등장 여부를 별도 선형 판독기로 검사해도 개선은 없었다. test macro AUC는 초기 writer 0.58587, 전체 순회 학습 뒤 0.58170이었다. 기존 복원 추첨 학습 뒤에는 0.58667이었다.

이번 학습이 선형적으로 읽을 수 있는 과거 단어 정보를 늘렸다는 근거는 없다. 그러나 이 검사는 개인 사실·정정·필요한 때의 반환을 직접 평가하지 않으며, 비선형 방식으로도 정보가 없다고 증명하지는 않는다.

**판단을 수정하면:** 학습 대화 일부를 아예 못 본 것은 분명 약점이었다. 하지만 같은 예산의 이번 단일 seed 실험에서는 그 문제를 고쳐도 개인별 기억이 살아나지 않았다. 직접 관측한 실패는 사람별로 거의 교환 가능한 상태와, 그 상태를 공통으로 보정하는 읽기다. 쓰기와 읽기 중 어느 지점에서 정보가 얼마나 막히는지는 아직 나누지 못했다.

또 샘플링을 바꾸면 노출 수뿐 아니라 순서와 반복 분포도 달라진다. 낮은 노출이 가진 모든 인과효과를 부정하는 결과는 아니다. 여러 번 본 MSC test의 탐색적 결과이므로 다른 seed와 사람 대화 자료에서 재현해야 한다. 실제 기억 텍스트/`NO_MEMORY` 출력과 자동 반환도 미검증이다.

## 후속 원인 분해: 쓰기와 읽기 경로를 각각 더 학습하기

이제 같은 모델에서 **쓰기를 더 배우는 것과 읽기를 더 배우는 것**을 분리했다. 시작점은 앞의 전체 순회 600스텝 체크포인트로 동일하다.

- 읽기 전용: bridge·write queries·update gate는 고정하고 잔차 reader만 학습한다.
- 쓰기 전용: reader는 고정하고 writer만 학습한다.
- 결합 대조: 두 경로를 모두 학습한다.

세 조건 모두 같은 512/96/96개 대화, seed 29, 순회 샘플링, 600 추가 스텝을 사용한다. 손실·학습률·검증 선택 절차도 같다. 기반 언어모델은 계속 고정했다. 다시 불러올 때 같은 모델이 되도록 학습 중 고정했던 부분의 가중치도 체크포인트에 함께 저장했다.

| 시작점에서 추가 학습 | 학습 파라미터 | valid `타인−자기` | test `빈−자기` | test `타인−자기` [95% 구간] |
| --- | ---: | ---: | ---: | ---: |
| 시작점 (추가 0스텝) | — | +0.00096 | +0.09181 | −0.00180 [−0.00384, +0.00017] |
| 읽기만 600스텝 | 297,793 | +0.00131 | +0.09154 | −0.00122 [−0.00323, +0.00077] |
| 쓰기만 600스텝 | 338,113 | +0.00673 | +0.10054 | +0.00511 [−0.00198, +0.01401] |
| 쓰기·읽기 600스텝 | 635,906 | +0.00201 | +0.10919 | +0.00144 [−0.00250, +0.00556] |

세 조건 모두 valid로 선택한 상태는 600스텝이었다. **읽기만 추가 학습한 경우에는 개인별 효과가 나타나지 않았다.** 쓰기만 학습하면 가장 많이 개선됐지만 test 구간에 0이 들어 있고 사전 목표 +0.02에도 크게 못 미쳤다.

둘을 함께 학습하면 빈 상태 대비 예측은 가장 좋아졌지만, 개인별 차이는 쓰기 전용보다 작았다. 추가 600스텝이 곧 개인별 기억의 개선을 보장하지는 않는다. 다만 단일 seed와 탐색적 test의 비교이므로 세 방식의 우열을 확정하지 않는다.

쓰기 전용 모델에는 작은 개인별 성분이 생겼을 가능성이 있다. valid 96개로 만든 공통 평균 상태를 test 모두에게 넣으면 NLL은 2.97458이었다. 본인 상태 2.96764보다 +0.00694 [95% 구간 +0.00001, +0.01563] 나쁘다. 이전 전체 순회 모델에서는 공통 평균이 본인보다 오히려 좋았다는 점과 다르다.

그래도 공통 평균이 빈 상태 대비 본인 상태 이득의 약 93%를 재현했다. 자기/타인 상태 코사인은 평균 0.99476에서 0.97749로 낮아졌다. 내용 토큰 64개의 선형 판독 test AUC는 초기 writer 0.58587, 전체 순회 모델 0.58170, 쓰기 전용 추가 학습 0.57821로 개선되지 않았다. 새 상태 차이가 어떤 개인 사실을 담는지는 아직 입증하지 못했다.

**현재 가장 좁혀 말할 수 있는 결론:** 개인별 정보가 *전혀* 없다는 주장은 맞지 않다. 하지만 현재 목적함수에서는 사람마다 다른 내용보다 공통 상태 보정을 훨씬 쉽게 학습한다. 쓰기를 더 학습하면 작은 개인별 차이를 만들 수 있는 반면 읽기만 더 학습해서는 그러지 못했다.

따라서 우선 의심할 곳은 쓰기와 상태 형성이다. 읽기의 표현력, 쓰기·읽기의 공동 최적화, 데이터 신호 부족을 각각 배제한 것은 아니다. 다음 주장에는 새 대화 분포와 다른 seed의 검증이 필요하다. 실제 기억 텍스트 출력과 자동 반환 시점도 아직 구현하지 않았다.

## 후속 원인 분해: 드문 유용 사례의 학습 신호가 묻히는가

마지막으로, 과거가 정말 유용한 사례가 적어서 평균 학습 손실에 묻히는지 살폈다. train 96개 원문 감사에서 본인 과거가 타인 과거보다 유리한 사례는 63개였다. 전체 `타인−자기` 평균은 +0.04589였지만 상위 24개는 +0.21223이었다.

원문을 읽는 이득이 소수 사례에 집중돼 있었다. 그래서 일반적인 다음 토큰 손실이 유용한 기억 신호를 희석한다는 가설을 시험했다.

학습 코드 (`train_stream_memory_human.py`; 원 저장소의 파일 참조)에 `--oracle-priority` 진단 옵션을 넣었다. 기본값은 꺼짐이다. **train 대화에만** 고정 언어모델로 자기/타인 과거 원문을 각각 직접 읽혀, 같은 미래 발화의 NLL 차이를 구한다. 차이가 양수인 상위 1/4에는 가중치 2.5, 나머지에는 0.5를 주어 평균 가중치를 1로 맞춘다.

MSC train 512개 중 자기 원문이 유리한 사례는 328개였고, 이 중 상위 128개를 강조했다. 수작업 사실·중요도 라벨은 쓰지 않는다. 하지만 과거 원문 전체와 미래 정답을 함께 본 교사를 이용하므로 **교사 기반 진단**이다. 최종 자율 기억 학습 방식이라고 해석하지 않는다.

비교할 두 실험은 전체 순회 600스텝 체크포인트에서 같은 writer만 600스텝 더 학습한다. 시작 가중치, 대화 순서, 손실 구성, 학습률, 검증 선택을 맞추고 **사례별 손실 가중치만** 바꾼다. 유용했던 사례를 더 강조하는 것 자체의 효과를 보려는 비교다.

| 쓰기 전용 추가 600스텝 | valid `타인−자기` | 기존 MSC test `타인−자기` [95% 구간] | 미학습 train 수신자 96개 `타인−자기` [95% 구간] |
| --- | ---: | ---: | ---: |
| 균등 가중치 | +0.00673 | +0.00511 [−0.00198, +0.01401] | −0.00114 [−0.00712, +0.00491] |
| 원문 효과 상위 사례 강조 | +0.00256 | −0.00077 [−0.00697, +0.00535] | +0.00184 [−0.00363, +0.00761] |
| 고정 LM + 원문 과거 직접 읽기 | — | +0.07766 | +0.03143 [+0.00760, +0.05434] |

표의 마지막 열은 앞서 학습에 쓴 train shuffle seed 29의 첫 512개와 겹치지 않는 **offset 1000의 수신 대화 96개**다. 두 체크포인트에 같은 사례와 정답 토큰을 처음 평가했으며, 수신 대화 ID의 교집합은 0이었다. 감사 평가에서도 체크포인트 가중치는 바뀌지 않았다.

다만 타인 기억을 제공하는 donor는 같은 전체 train 분할에서 뽑는다. donor 이력까지 미학습이라고 주장하지는 않는다. 원문 대조와 순환 모델은 입력 경로가 다르므로 절대 차이를 순수한 압축 손실로 해석하지 않는다.

**결론:** 원문 효과가 큰 사례에 이 방식으로 가중치를 더 주어도 개인별 기억은 살아나지 않았다. 기존 쓰기 전용 모델의 작은 test 이득 역시 새 미학습 수신자 집합에서는 재현되지 않았다. 원문에는 유용한 과거 차이가 있지만 순환 상태→읽기→출력에서는 대부분 전달되지 않는다는 관찰이 더 강해졌다.

그렇다고 드문 유용 사례의 신호가 중요하지 않다는 뜻은 아니다. 시험한 것은 가중치 형태 하나, 단일 seed, MSC 역할극 자료뿐이다. 사람별 사실을 정확히 복원하고 적절한 순간에 반환하는 최종 과제도 아직 검사하지 않았다.
