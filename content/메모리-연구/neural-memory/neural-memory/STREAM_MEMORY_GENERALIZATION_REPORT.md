# 기억 거리·잡담 위치 일반화 — 2026-09-27

후속 reader 고정/공동학습 대조: [[메모리-연구/neural-memory/neural-memory/STREAM_MEMORY_ACQUISITION_REPORT|새 사실 획득 보고서]]. 아래는 앞선 일반화 실패와 진단 기록이다.

결론: **단순히 800스텝으로 늘리는 것만으로 앞선 성능을 재현하지 못했고, 대화 수·길이 다양화는 오히려 악화됐다.** 질문 구간을 고정한 별도 검사에서 약한 seed는 사실 뒤 잡담 8구간에도 100%였지만 사실 앞 잡담 4구간에는 25%였다. 따라서 보존 시간만 늘리는 방향보다 이미 상태가 있는 상황에서 새 사실을 받아들이는 경로도 먼저 검사해야 한다. 일반적인 기억 모델 완성이나 노이즈내성 향상을 주장하지 않는다.

## 같은 업데이트 수 대조

이전 결과의 학습량 차이를 확인하려고, 같은 gated/query 구조를 짧은 단계 없이 기존 잡담 2·4·8턴에서 800스텝 학습했다. 두 seed 모두 읽기 오라클 없이 기억 파라미터를 초기화하고 대화별 상태는 0에서 시작한다. 마지막 미래 구간의 모든 대화 내용 next-token 손실을 사용한다.

| 학습 경로 | seed | 선택 스텝 | 시험 8지선다 | 전체 어휘 | 빈 상태 8지선다 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 길이에서 800스텝 | 7 | 750 | 19.79% | 17.71% | 12.50% |
| 기존 길이에서 800스텝 | 17 | 600 | 41.67% | 40.63% | 12.50% |
| 짧은 400 + 기존 길이 400, 이전 실행 | 7 | 두 번째 375 | 98.96% | 83.33% | 12.50% |
| 짧은 400 + 기존 길이 400, 이전 실행 | 17 | 두 번째 400 | 57.29% | 56.25% | 12.50% |

같은 800업데이트 조건에서도 짧은 단계부터 시작한 결과가 높았다. 따라서 앞선 개선을 단지 업데이트 수 증가로만 설명하기 어렵다. 단, curriculum은 단계 전환에 optimizer와 데이터 추출 RNG를 새로 시작하고 검증 최선 파라미터로 이어 학습한다. 처리한 입력 토큰 수·역전파 깊이도 다르다. 업데이트 수만 통제했으므로 짧은 거리 자체가 유일한 원인이라고 확정하지 않는다.

선택은 모든 조건에서 valid 자기 상태 NLL, 시험은 기존 96사례/12개 동일 잡담·질문 블록이다. 후보 8단어와 대화 틀이 공통인 탐색적 인공 과제이며 이 시험을 이미 반복 확인했다.

## 더 다양한 거리·위치 학습

다음 조건은 이전의 **읽기 오라클 없는 짧은 400스텝 체크포인트**에서 시작한다. 기존의 긴 400스텝 결과에 추가 학습한 것이 아니라, 두 번째 단계만 다른 자료로 교체한다.

- train 64블록/512사례, valid 16블록/128사례. 이전은 8블록/64사례, 4블록/32사례였다.
- 잡담 2·4·8·16·32턴과 뒤 잡담 3턴. 원래는 2·4·8턴과 뒤 잡담 3턴이었다.
- 두 번째 400스텝, batch 2, lr 0.0003, chunk 32, rank 4, 초기 gate 0.01, query 초기 크기 0.02.
- 개인 상태는 매 대화 0, 독립 에피소드 중 원문을 시간순으로 읽고 구간 사이 state 역전파를 유지한다.
- 사실 위치·정답 annotation은 이 non-oracle 학습 손실에 사용하지 않는다.

학습 예제 수와 길이 범위를 함께 바꿨으므로 개선 여부가 나와도 두 효과를 따로 분리한 대조는 아니다. 기존보다 더 긴 역전파로 계산량도 달라진다.

| seed | 두 번째 단계 선택 스텝 | 기존 시험 8지선다 | 전체 어휘 | 빈 상태 8지선다 |
| --- | ---: | ---: | ---: | ---: |
| 7 | 400 | 19.79% | 17.71% | 12.50% |
| 17 | 275 | 41.67% | 41.67% | 12.50% |

이 설정에서는 다양화가 성능을 올리지 못했다. 예제가 8배 늘었는데 두 번째 단계 스텝은 400으로 고정했으므로 예제당 평균 학습 횟수도 줄었다. 데이터가 많으면 일반화가 저절로 해결된다거나 많은 데이터가 본질적으로 해롭다는 주장 모두 지지하지 않는다.

## 공통 새 잡담 평가

기존 curriculum과 다양화 모델의 두 seed를 같은 새 잡담 추출(seed 2009), 24블록/192사례에서 비교한다. 별도 8·16턴 및 32·64턴 조건이다. 체크포인트는 각각 자기 valid NLL로 고르고 이 새 평가를 checkpoint 선택에 사용하지 않는다.

평가는 대조 블록별 사실 위치, 사실 뒤 구간 수, 정답 예측 위치, 자기/빈/교환/과거 단어 오라클의 후보·전체 어휘 예측을 기록한다. 사실 뒤 거리와 사실 이전 잡담 길이를 별도로 집계한다. 단, 두 축은 실제 자료에서 상관이 있으므로 실패 원인을 독립적으로 조작한 인과 실험으로 해석하지 않는다.

8개 단어가 같은 잡담/위치/질문을 공유하므로 신뢰구간은 단어별 독립 표본으로 취급하지 않고 **블록 단위 percentile bootstrap 2,000회**로 계산한다. 작은 인공 표본에서 얻은 탐색적 신뢰구간이다.

| 모델 | seed | 8·16턴, 8지선다 / 전체 어휘 | 32·64턴, 8지선다 / 전체 어휘 |
| --- | ---: | ---: | ---: |
| 이전 curriculum | 7 | 93.75% / 93.75% | 77.08% / 66.67% |
| 이전 curriculum | 17 | 46.88% / 46.88% | 26.04% / 23.44% |
| 다양화 | 7 | 19.79% / 19.79% | 12.50% / 11.98% |
| 다양화 | 17 | 19.79% / 19.79% | 12.50% / 12.50% |

모든 조건에서 빈 기억의 8지선다 정확도는 12.50%다. 다양화 모델의 긴 조건은 사실을 서로 교환해도 사실별 식별 성능이 우연 수준이었다. 자기 기억 NLL은 빈 상태보다 좋아도 단어 내용 사용에 성공한 것은 아니다.

긴 조건에서 이전 curriculum의 8지선다 95% block-bootstrap 구간은 seed 7 [67.19%, 85.94%], seed 17 [16.15%, 38.02%]다. 다양화 두 모델은 모두 [12.50%, 12.50%]였다. 반올림 전 값은 JSON에 있다.

동일 긴 조건에서 사실 **앞** 구간 수별 이전 seed 7의 정확도는 0~4구간 91.67%(9블록), 5~8구간 80%(5블록), 9구간 이상 62.50%(10블록)였다. seed 17은 각각 40.28%, 15%, 18.75%였다. 뒤 거리별 값도 함께 저장했지만 이 상관 집계만으로 새 사실 획득 실패와 이후 망각을 확정 분리하지 않았다.

## 질문·사실 위치를 고정한 좁은 개입

`diagnose_stream_memory_position.py`는 8단어 한 대조 블록에서 잡담 token stride(31토큰)를 0·4·8·16·32개씩 **사실 앞** 또는 **사실 뒤**에만 삽입한다. 사실의 구간 내부 위치와 최종 질문 원문 구간이 원래와 같은지 검사한다. 별도 학습은 없으며 비교 안에서는 가중치가 고정된다.

| 추가 잡담 구간 | seed 7 사실 앞 / 뒤 | seed 17 사실 앞 / 뒤 |
| --- | ---: | ---: |
| 0 | 100% / 100% | 100% / 100% |
| 4 | 100% / 100% | 25% / 100% |
| 8 | 100% / 100% | 25% / 100% |
| 16 | 100% / 100% | 25% / 87.50% |
| 32 | 100% / 100% | 25% / 50% |

이 표는 8지선다와 전체 어휘 단일 토큰 정확도가 같았다. 빈 상태는 12.50%, 교환 기억의 기증 단어 정확도는 자기 정확도와 같았다.

약한 seed에서 사실 뒤 잡담보다 사실 앞 잡담이 더 일찍 성능을 무너뜨렸다. 따라서 이 템플릿의 실패를 단순한 장기 보존 한계로만 설명하기 어렵다. 기존 상태를 바꾼 상황의 획득/표현/읽기 결합 문제를 좁히는 증거지만, 어떤 특정 gate 파라미터 하나가 유일한 원인이라고 확정하지 않는다. 강한 seed는 같은 검사에서 모두 맞혔으므로 구조가 원리적으로 불가능하다는 결과도 아니다.

하나의 템플릿과 반복된 인공 token 블록이므로 일반 사람 대화의 인과 효과 추정이 아니다. 첫 실행은 질문 앞에 잡담을 넣으면서 질문 구간의 일부 filler 토큰까지 바뀐다는 불변성 검사에서 중단됐다. 삽입 위치를 전체 마지막 구간 앞까지 당기고 단위 검사·실제 모델 재실행을 수행했다. 위 표는 `position-isolate-fixed` 완료 결과만 쓴다.

## 코드 및 검사

평가에 선택적 블록별 기록을 추가했다. 기존 aggregate 평가와 수치가 동일한지, 블록별 값을 평균하면 aggregate와 일치하는지 검사했다. 사실 앞 잡담과 사실 뒤 기억 거리의 집계가 뒤바뀌지 않는지, bootstrap 재현성/빈 입력 처리를 검사했다.

전체 검사 474 passed, 1 기존 경고. 실제 실행은 Apple MPS/float32다. 모델 구조·상태 크기는 바꾸지 않았다. 여전히 단일 고정 단어 과제이며 사람 대화, 여러 사실/정정, 기억 텍스트 반환과 반환/침묵 타이밍은 미검증이다.

다음의 좁은 목표는 **잡담 상태가 이미 있는 경우에도 새 사실을 획득하도록 학습하는지**다. 동일한 읽기 가중치를 고정한 쓰기 갱신 대조 등으로 획득과 읽기의 결합을 분리하고, 앞/뒤 잡담 개입과 같은 미사용 잡담 평가를 함께 통과해야 다음 단계로 간다. 현재 Transformer는 읽기와 쓰기 processor가 공유되므로 Q/V를 고정하면 그 쓰기 processor도 함께 고정된다는 제약을 명시해야 한다.

## 재현

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python run_stream_memory_control.py --seed 7 --steps 800 --loss-scope future-block --update-rule gated --gate-init 0.01 --write-query-scale 0.02 --output local-data/stream-rmt-control-gated-flat800-seed7.json
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python run_stream_memory_control.py --seed 7 --steps 400 --train-blocks 64 --valid-blocks 16 --train-noise 2 4 8 16 32 --valid-noise 2 4 8 16 32 --loss-scope future-block --update-rule gated --gate-init 0.01 --write-query-scale 0.02 --warm-start local-data/stream-rmt-control-gated-cold-short-seed7.pt --output local-data/stream-rmt-control-gated-diverse-seed7.json
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python eval_stream_memory_stress.py --checkpoint local-data/stream-rmt-control-gated-curriculum-seed7.pt --blocks 24 --seed 2009 --output local-data/stream-rmt-control-curriculum-sharedstress-seed7.json
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python diagnose_stream_memory_position.py --checkpoint local-data/stream-rmt-control-gated-curriculum-seed17.pt --output local-data/stream-rmt-control-position-isolate-fixed-seed17.json
```

seed 17은 학습 명령에 `--seed 17`과 해당 seed의 checkpoint/출력 파일을 쓴다. 두 모델의 stress seed는 동일한 2009다. 다양화 모델 평가는 checkpoint를 `stream-rmt-control-gated-diverse-seed{7,17}.pt`로 바꾸고 `stream-rmt-control-diverse-sharedstress-seed{7,17}.json`에 저장한다. 학습 산출물에는 선택한 trainable 가중치 `.pt`와 설정/전체 학습 기록 `.json`이 있다.
