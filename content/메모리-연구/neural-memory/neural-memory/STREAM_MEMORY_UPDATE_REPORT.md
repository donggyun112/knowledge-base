# 기억 갱신 경로 진단 — 2026-09-27

후속 [[메모리-연구/neural-memory/neural-memory/STREAM_MEMORY_GENERALIZATION_REPORT|일반화 보고서]]에서는 학습량을 같은 800스텝으로 맞춘 대조와 거리·위치를 다양화한 평가를 진행했다. 이 문서에는 그에 앞서 기억 갱신 구조를 바꾸고 짧은 거리부터 단계적으로 학습한 첫 실험을 남긴다.

**빈 기억에서 과거 대화를 읽은 뒤, 저장 중요도 라벨 없이 단일 사실을 학습하고 사용하는 경로를 얻었다.** 갱신량을 조절하는 게이트와 공유 쓰기 질의를 추가하고 짧은 거리부터 학습한 결과다. 두 seed의 시험 정확도는 8지선다 98.96% / 57.29%, 전체 어휘 83.33% / 56.25%였다. 기억을 비우면 둘 다 12.50%로 떨어졌고, 다른 대화의 기억으로 교환하면 그 기억을 제공한 대화의 단어를 답했다.

다만 seed와 기억 거리에 따른 성능 차이가 크다. 이 결과는 일반 대화의 기억이나 필요한 때 기억을 텍스트로 자동 반환하는 최종 목표까지 달성했다는 뜻은 아니다.

## 확인한 문제와 수정

먼저 확인한 문제는 **이미 읽을 수 있는 정보를 기존 순환 갱신이 훼손한다는 것**이었다. 따라서 이번 수정은 정보를 유지하는 경로와 학습 시작 조건에 초점을 맞췄다. 이 진단으로 원시 대화만을 이용한 학습 자체가 불가능하다고 결론내리지는 않는다.

`diagnose_stream_memory_update.py`에서는 이전 읽기 오라클 체크포인트의 모든 파라미터를 고정했다. 그런 다음 **실제로 과거에 등장한 단어**를 상태에 한 번 넣고, 정답 정보가 없는 동일한 잡담 블록을 반복 처리했다. 읽기 가중치와 질문은 모든 조건에서 같았다.

이렇게 시작한 이유는 새 정보를 저장하는 능력과 이미 저장된 정보를 유지하는 능력을 구분하기 위해서다. 초기화할 때 사실 위치를 직접 알려 주므로, 이 검사는 저장 방법을 학습했다는 증거가 아니다. 이미 읽을 수 있는 상태가 갱신을 견디는지만 확인한다.

96사례를 동일한 잡담과 질문을 공유하는 12개 대조 블록으로 구성해 측정했다. 표의 정답률은 8지선다이며, 전체 어휘 정확도는 어휘 전체에서 확률이 가장 높은 단일 토큰을 골랐을 때의 정확도다.

| 상태 갱신 | 잡담 갱신 횟수 | 8지선다 정확도 | 전체 어휘 정확도 |
| --- | ---: | ---: | ---: |
| 갱신 전 과거 단어 상태 | 0 | 93.75% | 83.33% |
| 전부 덮어쓰기 | 1 | 15.63% | 4.17% |
| 전부 덮어쓰기 | 16 | 13.54% | 3.13% |
| 고정 1% blend, 진단용 | 16 | 91.67% | 83.33% |
| 그대로 유지, 진단용 | 16 | 93.75% | 83.33% |

기억이 유지되지 않는 이유를 살펴보기 위해 한 대조 블록에서 최종 정답의 NLL을 상태까지 역전파했다. 덮어쓰기 조건의 `초기 상태 gradient norm / 최종 상태 gradient norm`은 8회 갱신에서 약 17,931배, 16회에서 약 1.26억 배였다. 반면 1%만 섞는 갱신의 16회 값은 0.861배였다.

이 수치는 해당 손실 방향에서 기울기가 얼마나 증폭되는지를 보여 준다. Jacobian의 최대 특잇값을 측정한 것은 아니며, 전체 학습 실패의 원인이 이것 하나라고 단정하지 않는다.

수정은 두 가지를 별도 옵션으로 추가했다.

- `gated`: 이전 상태를 직접 전달하는 경로에 슬롯별 학습 게이트를 붙였다. 게이트는 갱신량을 조절하며 초기값 0.01에서 학습을 시작한다. 처음 비어 있는 상태는 관측한 구간으로 채운다.
- 공유 쓰기 query: 쓰기 위치에 작은 학습 파라미터를 추가했다. 모든 대화가 공유하는 파라미터이며 개인 정보를 미리 넣는 장치가 아니다. 개인의 초기 기억은 여전히 0이고, 현재 텍스트에서는 이 쓰기 위치를 볼 수 없다.

이전 덮어쓰기 구현은 기본값으로 유지했다. 저장/검색 명령, 외부 사실 레코드, 벡터 DB를 추가한 것이 아니다. gate와 query도 대화 예측 손실로 학습한다.

## 같은 읽기 사전학습에서 시작한 대조

구조 변경의 효과를 비교하기 위해 표의 모든 조건을 동일한 읽기 오라클 체크포인트에서 시작했다. 이후 400스텝 동안은 빈 기억에서 실제 과거 대화를 읽고, 마지막 미래 구간의 **모든 대화 내용**을 예측하도록 학습했다. 이 추가 학습에서는 사실 위치나 저장 중요도 라벨을 알려 주지 않았다.

다만 출발점이 된 체크포인트는 사실을 직접 제공받는 특권 읽기 학습을 거쳤다. 따라서 추가 학습 단계와 전체 학습 이력을 구분해야 하며, 전 과정을 원시 대화만으로 학습했다고 주장하지 않는다.

seed 7에서 학습 64/검증 32/시험 96사례를 사용했다. 배치 크기는 2, 구간 길이는 32, AdamW 학습률은 0.0003이며 기울기 노름을 1로 제한했다. 체크포인트는 검증 자료에서 자기 상태를 사용한 NLL로 선택했다. 후보 8개 단어와 대화 틀은 학습·시험에서 같고, 잡담과 사실 위치는 달라진다.

| 변경 | 선택 스텝 | 시험 8지선다 | 전체 어휘 | 빈 상태 8지선다 |
| --- | ---: | ---: | ---: | ---: |
| 기존 덮어쓰기 | 400 | 12.50% | 10.42% | 12.50% |
| gate만 | 400 | 15.63% | 13.54% | 12.50% |
| 공유 query만 | 300 | 12.50% | 10.42% | 12.50% |
| gate + 공유 query | 375 | 86.46% | 80.21% | 12.50% |

수정 모델에 다른 대화의 기억을 넣자 원래 대화의 단어를 맞히는 비율은 2.08%, 기억을 제공한 대화의 단어를 맞히는 비율은 86.46%였다. 답이 기억 속 사실에 따라 바뀌므로 현재 문맥이나 읽기 가중치만으로 과제를 푸는 결과는 아니다. 다만 이 한 과제의 성공이 무엇을 저장해야 하는지 또는 언제 반환해야 하는지를 일반적으로 학습했다는 증거는 아니다.

같은 수정 모델의 새로운 잡담 추출(seed 1009)에서도 8·16턴 조건 73.96%, 32·64턴 조건 59.38%였다. 후자는 15~28개 구간에 해당하며 전체 어휘 정확도는 56.25%, 빈 상태는 12.50%였다. 길어지면 성능이 낮아진다. 새로운 단어/질문/사실 종류를 시험한 것은 아니다.

## 읽기 오라클 없이 시작하는 학습

다음에는 읽기 오라클 사전학습 없이 시작할 수 있는지 확인했다. 언어 모델이 이미 가진 언어 능력은 그대로 사용하고 기억 파라미터만 새로 초기화했다. 수정한 구조를 처음부터 기존 길이에서 400스텝 학습했지만 시험 정확도는 15.63%였다. 구조 변경만으로 원시 대화의 읽기·쓰기 공동학습이 해결되지는 않았다.

이에 사실 위치를 알려 주지 않은 채 짧은 거리부터 시작하는 단계적 학습(curriculum)을 시험했다. 첫 단계에서는 잡담 0·1턴과 뒤 잡담 1턴을, 두 번째에서는 기존 잡담 2·4·8턴과 뒤 잡담 3턴을 사용했다.

짧은 단계에서도 원래 사실이 마지막 원문 구간에 남아 있지 않은지 검사했다. 학습 목표는 마지막 구간에서 관측한 텍스트를 예측하는 것이며, 손실은 모든 앞선 구간까지 역전파한다. 구간별로 무엇이 중요한지 알려 주는 라벨은 쓰지 않는다.

seed 7을 첫 단계에서 400스텝 학습하자 짧은 검증에서는 100%를 맞혔지만 기존의 긴 시험에서는 19.79%에 그쳤다. seed 17도 짧은 검증은 100%였지만 긴 시험은 41.67%였다. 짧은 거리의 기억을 배웠다고 해서 긴 거리까지 곧바로 일반화되는 것은 아니었다.

seed 7은 짧은 거리 체크포인트에서 긴 거리 학습을 400스텝 더 진행했다. 전체 예산은 합계 800스텝이며 단계 전환 때 최적화기를 새로 초기화했다. 검증 NLL로 고른 체크포인트는 긴 단계의 375스텝이었다.

이 모델은 시험 96사례 중 95개를 맞혀 **8지선다 98.96% / 전체 어휘 83.33%**를 기록했다. 빈 상태에서는 12.50%였고, 기억을 교환하면 원래 단어는 0%, 기억을 제공한 대화의 단어는 98.96%였다. 이 실행의 기억 학습에는 oracle-prefix를 사용하지 않았다.

새 잡담 추출에서도 8·16턴 조건 92.71%(전체 어휘 80.21%), 32·64턴 조건 70.83%(전체 어휘 70.83%)였다. 후자는 466~860토큰, 15~28구간이며 빈 상태는 12.50%였다. 긴 거리는 여전히 성능이 떨어진다.

긴 거리 학습까지의 두 seed 결과는 다음과 같다. 두 번째 seed의 재현은 첫 seed보다 상당히 낮았다.

| seed | 긴 단계 선택 스텝 | 시험 8지선다 | 전체 어휘 | 빈 상태 8지선다 | 교환 상태 원래/기증 단어 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 7 | 375 | 98.96% | 83.33% | 12.50% | 0% / 98.96% |
| 17 | 400 | 57.29% | 56.25% | 12.50% | 6.25% / 57.29% |

두 seed 모두 짧은 단계와 긴 단계의 검증에서는 100%에 도달했지만, 시험 성능은 서로 달랐다. 잡담 위치와 거리가 달라질 때의 일반화가 아직 안정적이지 않다는 뜻이다. seed를 바꾸면 초기화·학습 순서·잡담 추출이 함께 달라지므로 이 차이를 어느 한 요소의 영향으로 분리할 수는 없다.

동일한 stress 잡담 추출을 seed 17 모델에 적용하면 8·16턴은 48.96%(전체 어휘 40.63%), 32·64턴은 21.88%(전체 어휘 21.88%)였다. seed 7의 92.71% / 70.83%만을 장기 보존 성능으로 대표시키면 안 된다. 두 모델 모두 stress 조건의 빈 상태는 12.50%였다.

8지선다 점수와 자유 출력 점수는 구분해야 한다. seed 7의 기본 시험에서 전체 어휘 정답률은 83.33%, 정답 NLL은 2.59785였다. 제한된 후보 안에서는 정답을 가장 높게 평가하더라도, 전체 어휘에는 그보다 높은 점수를 받는 다른 토큰이 있을 수 있다. 따라서 후보 제한 정확도만으로 출력 성공을 판정하지 않는다.

이 단계적 학습은 총 800스텝이지만 처음부터 긴 거리에서 시작한 cold 실행은 400스텝이었다. 당시에는 같은 예산의 800스텝 cold 대조를 하지 않았다. 따라서 **단계적 학습이 개선의 유일한 원인이거나 반드시 필요하다고 주장하지 않는다.** 여기서 확인한 것은 사실 위치를 직접 알려 주지 않아도 이 학습 경로를 통해 단순한 개인별 사실을 사용할 수 있다는 점이다.

## 검사와 한계

전체 검사에서 467개가 통과했고 기존 경고 1개가 남았다. 새 구조에 대해서는 빈 초기 상태에서의 읽기와 인과성(eager, SDPA), 패딩과 빈 구간을 넣어도 결과가 변하지 않는 성질, 미래 손실이 gate/query까지 역전파되는지, 체크포인트 누락을 검출하는지를 검사했다. 사실·정답 위치 표시를 바꿔도 오라클을 사용하지 않는 학습 손실이 같은지도 확인했다. 모든 실험은 Apple MPS/float32에서 실행했다.

첫 배치에서 측정한 bridge의 기울기 노름은 읽기 사전학습에서 시작한 덮어쓰기 조건이 약 298만, query만 추가한 조건이 약 3.12억, gate만 추가한 조건이 약 1.78만, 둘 다 추가한 조건이 약 6,956이었다. 모두 학습 전에 기울기를 제한한다. 처음의 소수 배치에서 얻은 값이므로 일반적인 안정성 순위를 정하거나 성공 원인을 독립적으로 입증하는 데 쓰지 않는다.

반복 확인한 작은 인공 시험이므로 탐색적 결과다. 아직 사람 대화 유효성, 여러 사실 보존/정정, 보지 않은 사실 종류, 기억 텍스트 출력, 반환/침묵 타이밍을 입증하지 않았다.

다음에는 처음부터 학습하는 cold 조건의 예산을 맞추고, 거리와 잡담 위치를 더 다양하게 바꿔 일반화 편차를 확인한다. 그 뒤 복수 사실·정정·새 단어와 실제 사람 대화로 검증을 넓힐 계획이다. 기억을 자동으로 반환하거나 침묵하는 인터페이스는 별도로 검증해야 한다.

## 실행 및 산출물

`local-data/stream-rmt-update-diagnostic-seed7.json`에 전체 보존/기울기 진단이 있다. `stream-rmt-control-{overwrite,gate-only,queries-only,gated}-warm-seed7.json/.pt`는 동일 초기 읽기 가중치 대조다. `stream-rmt-control-gated-warm-stress-seed7.json`은 새 잡담/긴 거리 평가다. `stream-rmt-control-gated-cold-seed7.json/.pt`는 읽기 오라클 없이 곧바로 기존 길이에서 학습한 실행이다.

`stream-rmt-control-gated-cold-short-seed{7,17}.json/.pt`와 `stream-rmt-control-gated-curriculum-seed{7,17}.json/.pt`가 oracle-prefix 없는 짧은/긴 단계다. 새 잡담/긴 거리 평가는 `stream-rmt-control-gated-curriculum-stress-seed{7,17}.json`에 있다. 이 문서의 중괄호 표기는 해당 이름의 여러 파일을 뜻한다.

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python diagnose_stream_memory_update.py --checkpoint local-data/stream-rmt-control-oracle-future-selection-fixed-seed7.pt --output local-data/stream-rmt-update-diagnostic-seed7.json
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python run_stream_memory_control.py --steps 400 --loss-scope future-block --update-rule gated --gate-init 0.01 --write-query-scale 0.02 --train-noise 0 1 --valid-noise 0 1 --train-trailing-noise 1 --valid-trailing-noise 1 --output local-data/stream-rmt-control-gated-cold-short-seed7.json
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python run_stream_memory_control.py --steps 400 --loss-scope future-block --update-rule gated --gate-init 0.01 --write-query-scale 0.02 --warm-start local-data/stream-rmt-control-gated-cold-short-seed7.pt --output local-data/stream-rmt-control-gated-curriculum-seed7.json
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python eval_stream_memory_stress.py --checkpoint local-data/stream-rmt-control-gated-curriculum-seed7.pt --output local-data/stream-rmt-control-gated-curriculum-stress-seed7.json
```

seed 17 재현은 짧은/긴 단계 모두 `--seed 17`과 해당 seed의 입력·출력 파일을 사용한다. stress seed는 두 모델 모두 기본값 1009다.
