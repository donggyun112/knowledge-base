# 메모리 모델 재설계 실험 보고 (2026-09-25 KST)

## 목표와 합격 기준

이 재설계는 과거 대화를 외부에서 검색해 붙이는 대신, 신경망 내부 상태에 남겨 나중 발화에 쓰게 하려는 실험이다. 과거 세션을 텍스트 토큰으로 읽으며 상태를 갱신하고, 새 에피소드는 **0에서 시작하는 기억**을 쓴다. 외부 임베딩 검색, 명시적인 key/value 기록, 도구 호출 문법은 없다.

별도로 과거 전체를 프롬프트에 넣는 조건도 둔다. 이는 학습할 메모리 모델이 아니라, 원문에 예측에 도움이 되는 정보가 있는지 확인하는 상한선 대조다.

핵심은 ‘기억이 있는 편이 낫다’와 ‘내 대화의 기억이 낫다’를 구별하는 것이다. NLL은 미래 발화의 정답 토큰에 준 확률로 계산하는 평균 예측 손실이며 낮을수록 좋다. 같은 현재 대화에서 이전 기억만 바꾼 뒤 `빈 상태 − 자기 상태`와 `타인 상태 − 자기 상태`를 계산한다. 두 차이가 모두 양수여야 자기 과거가 유리하다.

성공하려면 이 이득이 미사용 대화에서도 재현되어야 한다. 다만 검증 중 여러 설계를 시도했고 기존 MSC test split도 반복 확인했다. 아래 수치는 확정적 검증이 아닌 탐색적 결과다.

먼저 아주 작은 과제로 쓰기와 지연 읽기의 연결을 확인했다. 인공적인 단일 토큰 지연 복사에서는 자기 상태 정답률이 100%, 타인 상태는 0%였다. 따라서 신경망의 쓰기→나중 읽기 경로 자체가 작동할 수는 있다.

하지만 실제 발화 한 문장을 나중에 이어 맞히는 양성 대조는 실패했다. 이 차이는 현재의 압축·학습 방식이 자연어 내용을 보존하는 데 문제가 있다는 더 직접적인 경고다.

## 구현과 재현

- [[메모리-연구/neural-memory/neural-memory/RESTART_SPEC|재시작 설계]]: 엄격한 빈 상태, 내용 토큰만 채점, 상태 교환·노이즈·인과성 대조.
- 원시 사람 대화 오라클 (`eval_msc_history_oracle.py`; 원 저장소의 파일 참조): 동일한 현재 대화와 정답에 자기/타인/빈 과거만 교체해 고정 언어모델의 NLL을 비교.
- 처음 순환 메모리 (`neural_memory/recurrent_dialogue_memory.py`; 원 저장소의 파일 참조), 학습기 (`run_restarted_msc_memory.py`; 원 저장소의 파일 참조): 텍스트 토큰의 순환형 잠재 상태. 발화당 최대 48토큰, 8개 상태 위치, 폭 96. Apple MPS GPU에서 학습.
- 사전학습 기반 메모리 (`neural_memory/frozen_lm_memory.py`; 원 저장소의 파일 참조), 학습기 (`run_frozen_lm_memory.py`; 원 저장소의 파일 참조): 고정된 SmolLM2의 내부 토큰 상태를 최대 512개 과거 토큰에서 64토큰 단위로 읽고, 256차원 순환 상태 하나에 압축. 미래 국소 문맥은 별도 인코딩. 압축 상태만으로 예측을 보정하며 언어모델 가중치는 고정.
- 선택적 토큰 메모리 (`neural_memory/selective_token_memory.py`; 원 저장소의 파일 참조), 학습기 (`run_selective_msc_memory.py`; 원 저장소의 파일 참조): 과거 토큰 상태가 8개 잠재 슬롯에 경쟁적으로 쓰고, 미래 문맥이 슬롯을 선택해 읽음. 구간을 실제로 제거했을 때 정답 NLL이 악화되는 정도로 쓰기 점수를 지도하는 실험을 포함한다. 본 실험은 계산상 16토큰마다 하나의 상태를 사용했다. 모든 토큰을 입력하는 모드(`--token-stride 1`)는 소규모 실행 검사만 통과했으며 성능이 검증된 것은 아니다.
- 실제 수치 원본: `local-data/restart-oracle-test-96.json`, `local-data/restart-oracle-smollm-valid-96.json`, `local-data/restart-future-turn-seed7.json`, `local-data/frozen-lm-memory-distill-largeeval-seed7.json`, `local-data/frozen-lm-memory-scaled-seed7.json`, `local-data/selective-token-pilot-seed7.json`, `local-data/selective-token-ablation-seed7.json`, `local-data/selective-token-no-salience-seed7.json`.

## 현재 판단

실패를 데이터 부족 하나로 설명하기는 어렵다. 같은 자료의 과거 전체를 직접 읽으면 두 사전학습 모델 모두 타인 과거보다 유의하게 낫다. 활용할 정보는 있지만, 현재 압축 메모리는 그 차이를 안정적으로 남기지 못한다. 학습 대화를 1200→2000개, 상태를 256→512차원으로 늘려도 이 결론은 바뀌지 않았다.

무엇을 쓸지 선택하는 구조와 질문에 따라 읽는 구조, 구간 제거에 기반한 쓰기 지도도 추가했다. 그러나 현재 400쌍 파일럿에서는 학습 밖 대화의 개인별 이득이 확인되지 않았다. **빈 상태보다 낫다는 비교만으로는 개인 기억이라고 말할 수 없다.**

구간 제거 지도는 과거의 일부를 실제로 지웠을 때 예측이 얼마나 나빠지는지를 쓰기 신호로 삼는다. 입력 변경 효과를 측정한다는 장점은 있지만, 토큰을 지우면 문맥 길이도 달라진다. 따라서 그 점수를 정확한 정보 기여도 라벨이라고 단정하지 않는다.

최종 전체 테스트는 `422 passed, 1 warning`이었다. 경고는 기존 `test_trainable.py`의 기울기 추적 텐서를 실수로 변환하는 코드에서 나왔으며 이번 메모리 실험 실패와는 별개다.

## 2026-09-26 추가: 같은 읽기 통로의 원인 분리

앞선 실패를 읽기 구조 자체의 한계로 돌릴 수 있는지 [[메모리-연구/neural-memory/neural-memory/MEMORY_PATH_DIAGNOSTIC_REPORT|별도 진단 보고]]에서 다시 확인했다. 같은 residual 읽기 통로로 단일 사실을 나중에 회상하는 양성 대조를 했다. 정확한 과거 근거를 주는 오라클은 100%, 모든 토큰을 입력받아 상태를 쓰는 순환 모델은 두 seed에서 약 90%를 맞혔다.

따라서 자연어 실패를 ‘이 읽기 구조로는 원래 불가능하다’거나 ‘압축만의 문제다’라고 단정할 수 없다. 앞서 비교했던 전체 과거 프롬프트 오라클과 residual 메모리는 애초에 서로 다른 읽기 경로였다는 점도 고려해야 한다.

입력 간격을 통제한 결과는 더 분명했다. 같은 seed·400스텝·사전학습 없는 메모리에서 모든 토큰을 넣으면 93.23%, 16토큰마다 넣으면 12.50%였다. 2000스텝에서는 각각 83.85%, 17.71%였다.

이는 인공 양성 대조에서 입력 간격과 긴 잡담으로의 일반화에 문제가 있음을 보여준다. 실제 MSC 실패의 원인을 확정하는 결과는 아니다. 자동 저장 판단, 반환 타이밍, 다중 사실 기억도 여전히 미검증이다. 추가 검사를 포함한 최신 전체 테스트는 `430 passed, 1 warning`이다.
