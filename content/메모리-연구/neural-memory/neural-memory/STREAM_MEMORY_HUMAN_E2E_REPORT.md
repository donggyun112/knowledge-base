# 실제 사람 대화 연속성 평가 — 2026-09-28

## 판정

합성 대화에서 잘하던 모델이 실제 사람 대화에서도 과거를 활용하는지 확인했다. 결론부터 말하면, 현재 StreamRMT 체크포인트는 **실제 사람 대화에서 유용한 과거 기억을 입증하지 못했다.**

같은 96개 대화에서 언어모델이 과거 원문을 직접 읽으면 예측이 좋아졌다. 그러나 과거를 작은 순환 상태로만 넘겨받은 모델은 자기 과거를 넣었을 때가 빈 과거보다 오히려 불리했다. 개선 후보도 이 결과를 뒤집지 못했다. 후보는 채택하지 않으며 메모리 E2E 성공이라고 주장하지 않는다.

이번에 묻는 것은 **과거 대화를 읽고 만든 내부 상태가 나중 대화의 예측에 도움이 되는가**다. E2E는 입력부터 최종 출력까지 전체 기능을 뜻하지만, 여기서는 그중 한 단계만 검사한다.

아직 모델에는 기억을 텍스트로 반환하는 헤드, 반환할 것이 없을 때 `NO_MEMORY`를 내는 헤드, 언제 반환할지 결정하는 헤드가 없다. 따라서 엄밀한 의미의 자동 메모리 반환 E2E는 아직 시험할 수 없다.

## 프로토콜

- **자료와 예측 대상:** 로컬 MSC `valid`의 사람-사람 페르소나 역할극 대화 96개를 사용했다. 마지막 세션의 두 발화를 보여 준 뒤 세 번째 발화 2,944토큰을 예측한다. 처음 16개에서 파일럿을 실행하고 같은 고정 절차를 96개로 늘렸다. MSC는 자연스러운 사적 대화가 아니고 이 split도 이전 연구에서 이미 본 자료이므로 결과는 탐색적이다.
- **과거를 전달하는 방법:** 각 대화 이전 세션의 최근 최대 12발화/1,800자/384토큰을 시간순으로 읽어, 0에서 시작하는 8 × 576 잠재 상태를 갱신한다. 이후 메모리 모델에 과거 원문을 다시 주지 않는다. **96개 모두 과거 이력 일부가 잘렸다.** 현재 접두부와 정답 발화는 잘리지 않았지만, 전체 장기 이력을 평가한 것은 아니다.
- **세 조건을 비교하는 이유:** 같은 현재 두 발화와 같은 정답 토큰에 자기 과거 상태, 빈 *이전* 상태, 다른 대화의 과거 상태를 넣는다. 빈 상태와 비교하면 기억 상태의 존재가 도움이 되는지 알 수 있고, 다른 상태와 비교하면 해당 대화의 내용이 중요한지 알 수 있다. 빈 조건도 현재 두 발화는 정상 처리한다. 정답 발화는 이전 상태를 만드는 데 사용하지 않는다.
- **예측 점수의 범위:** 첫 정답 토큰 이후에는 앞선 정답 토큰을 제공하는 teacher forcing으로 손실을 잰다. 따라서 모델이 혼자 끝까지 발화를 생성하는 시험은 아니다.
- **원문 직접 읽기 대조:** 원래 SmolLM2와 체크포인트의 Q/V adapter를 적용한 SmolLM2가 각각 과거 **원문**을 직접 읽는다. 원문에는 쓸 만한 정보가 있는지 확인하려는 대조다. 순환 상태와는 입력 방식, 위치, attention 경로가 다르므로 절대 NLL 격차를 압축 손실 하나의 인과 효과로 볼 수 없다.
- **표 읽는 법:** NLL은 정답 예측 손실이며 낮을수록 좋다. 각 대화의 정답 토큰 평균을 구한 뒤 96개 대화에 같은 가중치를 주었다. `빈−자기`가 양수여야 자기 과거가 더 유리하다. 95% 구간은 대화 단위 paired bootstrap 2,000회로 구했다. donor 재사용과 이미 본 split이라는 한계 때문에 구간도 탐색적으로 해석한다.

| 조건 | 자기 과거 NLL | 빈 과거 NLL | 빈−자기, 95% 구간 | 다른 과거−자기, 95% 구간 |
| --- | ---: | ---: | ---: | ---: |
| 원본 LM + 원문 직접 읽기 | 2.979 | 3.085 | +0.106 [0.077, 0.134] | +0.070 [0.042, 0.098] |
| 원래 rank-4 adapter + 원문 직접 읽기 | 4.764 | 5.322 | +0.558 [0.464, 0.651] | +0.108 [0.032, 0.182] |
| 원래 rank-4 adapter + 순환 기억 | 8.517 | 8.405 | -0.112 [-0.182, -0.042] | -0.050 [-0.141, 0.036] |
| 보호된 rank-8 후보 + 원문 직접 읽기 | 4.764 | 5.314 | +0.550 [0.456, 0.643] | +0.111 [0.038, 0.187] |
| 보호된 rank-8 후보 + 순환 기억 | 8.509 | 8.391 | -0.118 [-0.195, -0.046] | -0.060 [-0.153, 0.032] |

두 체크포인트는 정확히 같은 문제를 풀었다. 평가 대화 ID, 비교 상태를 제공한 donor, 정답 토큰 해시가 모두 일치했다. 첫 정답 토큰에서 가장 높은 점수의 후보(argmax)가 맞은 비율은 두 순환 기억 모델 모두 1/96이었다. 원래 adapter에서는 자기 과거의 NLL이 빈 과거보다 낮았던 대화가 37/96개뿐이었다.

## 해석과 남은 일

원문을 직접 읽으면 좋아졌다는 것은 이 96개 발화에 예측에 쓸 수 있는 과거 정보가 있다는 뜻이다. 그런데 학습된 adapter의 대화 NLL부터 원본 LM보다 높았고, 같은 adapter 안에서도 원문을 읽는 경우보다 순환 기억을 읽는 경우의 손실이 컸다.

따라서 두 문제가 함께 관찰된다. **합성 과제에 맞춘 학습 뒤 일반 언어모델 성능이 떨어졌고, 순환 인터페이스를 통한 기억 전달도 잘되지 않았다.** 다만 이 실험만으로 내부 상태 압축, attention/position 구성, 학습 분포 차이 중 하나를 유일한 원인으로 정할 수는 없다.

다음에는 사람 대화의 긴 이력을 더 충실하게 학습·검증한다. 같은 기반 모델(backbone)에서 원문을 읽을 때와 순환 상태를 읽을 때의 손실을 줄이는 것이 먼저다.

그 뒤에 기억 텍스트, `NO_MEMORY`, 반환 시점 출력을 설계하고 학습해야 한다. 마지막으로 실제 필요한 순간에만 정확한 기억을 반환하는지 별도로 평가한다. 이 단계 전에는 합성 정정 과제의 개선만으로 E2E 성능을 주장하지 않는다.

재현: `eval_stream_memory_human.py`의 `--raw-oracle --adapted-plain-control --device mps --limit 96`을 원래 체크포인트에, `--adapted-plain-control --device mps --limit 96`을 보호 후보에 적용했다. 결과는 각각 `local-data/stream-rmt-human-valid-96-adapted-seed7.json`, `local-data/stream-rmt-human-valid-96-protected-seed7.json`에 있다. 둘 다 학습 스텝 0, adapter 비트 동일성 검사 통과. 스크립트는 기존 결과 파일 덮어쓰기를 거부하며 대화 원문 대신 ID와 정답 토큰 해시를 보고한다.

## 합성 과제 최신 모델의 사람 대화 전이 검사 — 2026-09-29

합성 과제에서 기억할 거리를 다양하게 학습하면 사람 대화에도 도움이 되는지 다시 비교했다. 하나는 단일 거리 모델, 다른 하나는 1·3·6턴 혼합 거리 모델이다. 둘 다 **MSC로 추가 학습하지 않은** 합성 과제 체크포인트다.

먼저 사람 대화 평가기가 체크포인트의 `write_mode`, 첫 쓰기 강제 여부, 게이트 옵션을 정확히 복원하도록 수정했다. 동일한 MSC valid 96개·정답 2,944토큰에서 평가했으며 두 결과의 대화 ID·donor ID·정답 토큰 해시는 모두 같다.

| 모델 | 자기 과거 NLL | 빈−자기 [95% 구간] | 타인−자기 [95% 구간] | 첫 정답 토큰 정확도 |
| --- | ---: | ---: | ---: | ---: |
| 합성 단일 거리 | 8.986 | −0.065 [−0.200,+0.070] | +0.046 [−0.046,+0.143] | 1/96 |
| 합성 1·3·6턴 혼합 거리 | 7.786 | +0.702 [+0.571,+0.833] | +0.019 [−0.062,+0.102] | 0/96 |
| 원본 LM + 과거 원문 직접 읽기 | 2.979 | +0.106 [+0.077,+0.134] | +0.070 [+0.042,+0.098] | 28/96 |

혼합 거리 학습 후에는 빈 이전 상태보다 과거 상태를 넣었을 때의 이득이 크게 늘고 절대 NLL도 낮아졌다. 그러나 **타인의 과거와 구별되는 개인별 효과는 입증하지 못했다.** 과거 상태의 존재가 도움을 준 것과 특정 사람의 정보를 쓴 것은 여전히 구별해야 한다.

원본 LM의 원문 직접 읽기는 입력 경로가 다르므로 절대 NLL 차이를 순수한 압축 손실로 보지 않는다. 기존 valid split도 반복 관찰했고, 점수는 teacher-forced 미래 발화 예측뿐이다. 무엇을 저장했는지, 자유 텍스트 기억 반환, `NO_MEMORY`, 반환 시점은 아직 학습·평가하지 않았다. 따라서 이 결과로 체크포인트를 채택하지 않는다.

추가 결과: `local-data/stream-rmt-cf-gatedfirst-{directlong,multihorizon-directlong}-seed41.pt`에 대한 `local-data/stream-rmt-cf-gatedfirst-human-valid96-seed7.json`, `local-data/stream-rmt-cf-gatedfirst-multihorizon-human-valid96-seed7.json`. 회귀 테스트 **750개 통과**(기존 경고 1개).

## 제외된 사람 대화 요약문 지도학습 파일럿 — 2026-09-29

**2026-09-30 정정:** 아래 실험은 사람이 쓴 기억 요약문을 학습 정답으로 주었다. 이는 원 대화만으로 저장 가치와 반환을 스스로 학습해야 한다는 연구 목표와 다르다. 수치는 해당 지도 과제의 기록으로만 남기고, 목표 메모리 모델의 성공·실패 근거에서 제외한다. 학습기의 요약문 정답 분기는 제거했다.

제거 후 학습기의 입력·정답은 MSC 대화 원문과 그다음 실제 발화뿐이다. `local-data/stream-rmt-human-unlabeled-smoke-seed30.json`은 MPS에서 2/2/2개 대화·1스텝으로 경로 실행만 확인한 결과이며 성능 평가가 아니다. 전체 Python 테스트 751개 통과(기존 경고 1개).

이 파일럿 당시에는 과제를 미래 발화 예측에서 **이전에 나눈 대화의 중요한 내용을 텍스트로 예측하기**로 좁혔다. MSC 첫 세션의 사람-사람 대화를 빈 상태에서 시간순으로 읽게 하고, 그 대화에 대해 사람이 쓴 Speaker 1 요약문을 정답으로 주었다. 정답 요약문은 입력 이력에는 넣지 않았다.

그래도 사람이 작성한 요약문을 정답으로 쓰므로 **지도 학습**이다. 저장 판단이나 반환 시점을 모델이 자율적으로 배운 것이 아니다. 135M 언어모델을 고정하고 순환 기억 경로 635,906개 파라미터만 MPS에서 학습했다. 평가 NLL도 정답 앞부분을 제공하는 teacher forcing으로, 자유 생성 결과가 아니다.

학습 256개·검증 32개·테스트 32개 대화로 300스텝 실행했고, 검증 기준으로 선택된 것은 50스텝이었다. 테스트의 `빈−자기` NLL은 **+0.235** [0.200, 0.266]으로 유리했지만, 개인별 구별을 보는 `타인−자기`는 **−0.008** [−0.029, +0.012]이었다. 첫 토큰 정확도도 자기·타인 모두 31/32로 같았다.

반대로 과거 **원문을 직접 읽은** 고정 언어모델의 테스트 `타인−자기`는 +1.341이었다. 즉 자료 안에 개인별 정보는 있다. 하지만 현재 순환 모델의 개선을 개인별 내용 사용으로 설명할 수는 없다. 선택된 50스텝까지 실제로 본 학습 대화 32개에서도 `타인−자기`는 −0.025 [−0.065, +0.002]였다.

소수 대화를 외울 능력이 없는지, 새 대화로 옮기지 못하는지 나누어 보려고 학습 대화 8개만 300스텝 반복했다. **마지막 학습 상태**에서는 8개 모두 자기 이력이 타인 이력보다 유리했고 `타인−자기` NLL이 +0.687 [0.441, 0.938]이었다.

그러나 같은 상태를 처음 보는 검증 대화 32개에 적용하면 `빈−자기` −1.028, `타인−자기` −0.010이었다. 검증 점수가 나빠져 실제 선택된 체크포인트는 학습 전인 0스텝이다. 소수 대화를 외우는 것은 가능했지만, 이 설정으로 새 대화의 중요 정보를 일반화하지 못했다. 8개 학습 사례의 구간을 독립적인 일반화 근거로 쓰지 않는다.

당시 판정은 모델을 채택하지 않는 것이었지만, 위 정정에 따라 **이 파일럿은 목표 메모리 모델의 성능 판정 자체에 쓰지 않는다.** `NO_MEMORY`, 기억 반환 시점, 자유 텍스트 반환도 이 파일럿에서 구현·평가하지 않았다. 원문 직접 읽기와 순환 상태의 절대 NLL 차이는 입력 경로가 달라 순수 압축 손실로 해석하지 않는다. MSC는 페르소나 역할극이며 valid/test는 과거에 이미 확인한 split이므로 모든 수치는 탐색적이다. 결과 파일: `local-data/stream-rmt-msc-summary-cf-300-seed29.json`, `local-data/stream-rmt-msc-summary-train-seen-seed29.json`, `local-data/stream-rmt-msc-summary-overfit8-last-seed29.json`. 당시 회귀 테스트 **751개 통과**(기존 경고 1개).
