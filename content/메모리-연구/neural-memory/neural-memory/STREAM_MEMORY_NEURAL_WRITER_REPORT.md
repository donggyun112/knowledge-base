# 학습형 writer와 상태 소실 진단 — 2026-09-28

## 결론

이 실험은 ‘읽을 때 문제가 있는가, 아니면 그 전에 정보가 제대로 저장되지 않는가’를 좁히기 위해 쓰기 모듈(writer)을 바꿨다. 현재 구간 끝의 기억 위치에서 상태를 만드는 기존 suffix writer와, 기억 슬롯이 관측 텍스트에 직접 attention을 보내는 학습형 cross-attention writer를 비교했다.

새 writer도 이번 반사실 대화 과제에서 개인별 단어를 기억하지 못했다. 자기 상태와 다른 대화의 상태 어느 쪽을 넣어도 8개 후보 중 정답률은 우연 수준인 12.5%였다. 기존 suffix writer보다 나아지지 않았다. 새 writer까지 학습 기울기는 도달했으므로, 단순히 역전파 연결이 끊긴 결과는 아니다. 현재 학습 목표와 반복 갱신 아래에서 단어별 차이를 만들고 유지하는 데 실패했다.

## 조건

- **기억해야 할 것:** 과거 발화 `Me: My secret word is <word>`에 나온 단어를 잡담 뒤에 묻는다. 8-way는 후보 여덟 개 중 맞히는 평가다. 반사실 블록 안에서는 단어와 정답만 바꾸고 잡담·질문·길이를 똑같이 둔다. 그래서 질문의 모양만으로 답을 구별할 수 없다. 정답 단어는 마지막 원문 구간에 없다.
- **자료 분할:** 학습 16블록/128사례, 검증 4블록/32사례, 테스트 12블록/96사례다. 테스트에서는 잡담을 8·16턴으로 늘렸다.
- **고정한 조건:** SmolLM2-135M-Instruct는 고정하고, 8×576 순환 상태와 같은 학습형 residual adapter 읽기를 쓴다. LoRA rank는 0이다. 쓰기만 기존 suffix 또는 새 cross-attention으로 바꾸며, 갱신 방식은 상태를 교체하는 overwrite다. Apple MPS/float32, seed 41, 300스텝, batch 2, lr 0.0003으로 실행했다.
- **학습과 선택:** 중요도·사실 위치 라벨이나 정답 토큰을 특별한 경로로 보내는 특권 라우팅은 없다. 마지막 미래 구간의 **대화 내용 전체**에서 다음 토큰 손실을 학습한다. 검증 자료의 자기 상태 NLL로 체크포인트를 선택했다. 정확한 과거 토큰을 직접 주는 oracle은 학습 경로가 아니라 별도 진단 조건이다.

| 쓰기 방식 | 선택 스텝 | 테스트 자기/교환/빈 NLL | 자기/교환 8-way 정확도 | 자기 전체 어휘 정확도 |
| --- | ---: | --- | --- | ---: |
| 기존 suffix | 300 | 3.775389 / 3.775471 / 15.226600 | 12.5% / 12.5% | 11.46% |
| 학습형 attention | 250 | 4.357145 / 4.357146 / 15.226600 | 12.5% / 12.5% | 2.08% |

표에서 빈 상태보다 NLL이 크게 낮아졌다고 바로 기억 성공은 아니다. 기억 통로가 공통적인 문장 형식이나 과제 패턴만 보정해도 그런 개선이 생긴다. 이번에는 자기 상태와 교환 상태의 손실이 사실상 같았다. 어떤 단어를 저장했는지에 따라 예측이 달라졌다는 근거가 없다.

전체 어휘 정확도 역시 정답 단어를 구별하지 않고 빈번한 한 단어만 출력해도 일부 얻을 수 있다. 그래서 상태 교환 결과와 함께 봐야 한다.

## 상태가 사라지는 위치

단어 차이가 어디에서 사라지는지 보려고 두 시점을 측정했다. 하나는 사실이 들어 있는 구간을 막 읽은 직후, 다른 하나는 잡담을 거쳐 질문을 받기 직전이다. 선택된 체크포인트에서 같은 반사실 블록의 서로 다른 상태를 교환해 수치 차이의 RMS를 구했다. RMS는 여러 좌표의 차이를 하나의 크기로 요약하는 값이다. 상태 자체의 RMS로 나눈 상대 차이도 함께 기록했다.

| 쓰기 방식 | 사실 직후 상태 차이 | 질문 직전 상태 차이 | 감소 배율 | 질문 직전 상대 차이 |
| --- | ---: | ---: | ---: | ---: |
| 기존 suffix | 0.053433 | 0.001719 | 약 31배 | 0.000871 |
| 학습형 attention | 0.004098 | 0.0000337 | 약 121배 | 0.0000170 |

새 attention writer는 사실 구간 직후부터 단어별 상태 차이가 더 작았다. 뒤의 잡담 구간을 지나면 그 차이가 거의 사라졌다. 질문 위치에서 자기/교환 상태가 만든 후보 단어 점수(logit)의 RMS 차이도 0.0000388뿐이었다. 상태의 차이가 출력 점수까지 거의 전달되지 않은 것이다.

이는 **현재 구현에서 쓰기·보존 경로가 막히는 지점이라는 강한 근거**다. 다만 상태 차이가 작다는 것만으로 읽기의 기여를 배제할 수는 없다. 또한 ‘사실 직후’ 측정은 단어가 구간에 처음 등장하는 순간에 맞춘 별도의 인과 개입 시험은 아니다.

## 구현·검증·범위

- 모델 (`neural_memory/stream_recurrent_memory.py`; 원 저장소의 파일 참조)에 슬롯이 관측 텍스트 hidden state를 cross-attend하는 `attend` 쓰기 모드를 추가했다. 기존 `suffix` 기본 동작은 유지했다. 입력은 텍스트 토큰이고, 외부 key-value 저장소나 검색 인덱스는 없다.
- 대조 실행기 (`run_stream_memory_control.py`; 원 저장소의 파일 참조)에 쓰기/읽기 방식 선택, writer 기울기 및 상태·logit 교환 차이 계측을 추가했다. 첫 단계 attention writer gradient norm은 8.11로 0이 아니었고, 고정 backbone에는 gradient가 없었다.
- 상태 진단 (`diagnose_control_state_spread.py`; 원 저장소의 파일 참조)은 저장된 체크포인트에서 사실 직후와 질문 직전의 상태 차이를 별도로 계산한다.
- 이것은 단일 인공 사실 과제의 한 seed 진단이며 실제 사람 대화 E2E, 장기 보존, 자동 반환 타이밍, 텍스트 메모리 출력의 성공을 뜻하지 않는다. `past_token_oracle`은 이 checkpoint로 읽기만 했으므로 그 낮은 성능을 읽기 인터페이스의 절대 한계로 해석하지 않는다.

원자료: `local-data/stream-rmt-control-suffix-residual-rank0-seed41.json`, `local-data/stream-rmt-control-attend-residual-rank0-seed41-diagnostic.json`, `local-data/stream-rmt-control-suffix-residual-rank0-seed41-state-spread.json`, `local-data/stream-rmt-control-attend-residual-rank0-seed41-state-spread.json`. 각 실행기의 같은 이름 `.pt`가 선택된 학습 가중치를 보존한다.

## 후속: 보존 게이트와 짧은 거리부터 학습

다음에는 ‘처음에 약하게 써진 것인가, 나중에 지워진 것인가’를 나누어 봤다. seed 41, 고정 backbone, rank 0, residual 읽기, 8개 슬롯을 유지하고 옛 상태를 일부 남기는 `gated` 갱신을 검사했다.

attention writer에 게이트를 넣어 긴 거리로 바로 300스텝 학습해도 테스트 8지선다 자기/교환 정답률은 모두 12.5%였다. 상태 차이는 사실 직후 0.000668에서 질문 직전 0.000578로 대부분 **유지**됐다. 그러나 처음 만들어진 차이부터 너무 작아 답을 구별하지 못했다. 지워지는 문제를 줄여도 사실을 충분히 강하게 쓰는 문제는 남는다.

거리 자체가 학습을 어렵게 하는지도 비교했다. oracle 라우팅 없이 짧은 잡담 0·1턴과 뒤 잡담 1턴으로 먼저 400스텝 학습하고, 필요하면 기존의 긴 거리로 400스텝 더 학습하는 방식이다. 기존 suffix 쓰기에는 공유 쓰기 query 0.02를 사용했다. 두 방식 모두 마지막 미래 구간의 대화 내용 전체에 대한 next-token 손실을 썼다.

짧은 단계에서 attention writer의 검증 정답률은 평가한 모든 스텝에서 12.5%였다. 따라서 이 후보는 긴 단계로 넘기지 않았다.

| 경로 | 짧은 단계 검증 자기/교환 | 기본 긴 테스트 자기/교환 | 더 긴 32·64턴 새 잡담 자기/교환 |
| --- | --- | --- | --- |
| 게이트 + attention writer, 짧은 단계 400스텝 | 12.5% / 12.5% | 12.5% / 12.5% | 미평가 |
| 게이트 + suffix writer, 짧은 단계 400스텝 | 25.0% / 12.5% | 13.54% / 12.5% | 미평가 |
| 게이트 + suffix writer, 이어서 긴 단계 400스텝 | 12.5% / 12.5% (긴 검증) | 17.71% / 9.38% | 12.5% / 12.5% |

표의 마지막 행은 긴 단계에서 검증 NLL이 가장 낮았던 125스텝의 체크포인트다. 긴 단계의 첫 25스텝부터 검증 대화별 상태 차이가 약 0.077에서 0.000002로 줄었다. 이후 모든 검증 스텝의 정답률은 12.5%였다. 기본 긴 테스트에서 보인 작은 자기/교환 차이가 검증에서는 재현되지 않은 셈이다.

새 잡담 seed 1009의 8·16턴 96사례에서는 자기 17.71%, 교환 10.42%였다. 하지만 95% 블록 bootstrap 정확도 구간 [12.5%, 26.04%]에는 우연 수준이 포함됐다. 더 긴 32·64턴에서는 두 조건 모두 12.5%였고 최종 상태 차이는 0.00000024였다. **오래 유지되는 대화별 기억에 성공했다고 판단하지 않는다.**

이 비교로 ‘정보 획득’과 ‘정보 보존’을 구분할 수 있다. 획득은 서로 다른 단어가 처음부터 다른 상태를 만들게 하는 것이고, 보존은 그 차이가 잡담 뒤까지 남게 하는 것이다. 고정 게이트만으로는 attention writer의 처음부터 약한 신호를 충분히 키우지 못했다. suffix + query는 짧은 거리에서 일부 신호를 얻었지만, 긴 거리 학습과 평가로 안정적으로 옮기지 못했다.

다만 두 writer는 파라미터 구조와 초기화가 다르다. 단일 seed 결과만으로 어느 방식이 인과적으로 더 우월한지 확정하는 비교는 아니다. 실제 사람 대화 E2E나 기억 반환 기능도 여기서는 평가하지 않았다.
