# 연속 대화 메모리 파일럿 — 2026-09-27

후속으로 같은 읽기 가중치를 고정한 갱신 진단, gate/query 제거 대조, 짧은 거리부터의 학습을 수행했다. 아래는 최초 파일럿 기록이며 최신 결과는 [[메모리-연구/neural-memory/neural-memory/STREAM_MEMORY_UPDATE_REPORT|갱신 진단 보고서]]에 별도로 보존한다.

## 결과 요약

이 파일럿은 사람이 ‘중요하니 저장하라’고 표시하지 않아도, 대화의 다음 토큰을 예측하는 과정에서 기억을 배울 수 있는지 묻는다. 이를 위해 앞 구간에서 만든 상태를 다음 구간으로 넘기는 순환 기억 경로를 구현했다.

넘겨받은 기억은 Transformer의 입력부터 처리에 참여한다. 뒤 구간에서 예측이 틀리면 그 학습 신호가 앞선 기억 갱신까지 돌아간다. 언어모델의 마지막 내부 표현에 값을 더하던 기존 hidden residual 보정 모듈과는 다른 구조다.

**현재 구현·학습 조건에서는 대화별 정보를 보존한 기억의 이득을 확인하지 못했다.** 사람 대화 파일럿의 두 seed 모두 자기 대화에서 만든 상태가 다른 대화의 상태보다 명확하게 낫지 않았다. 인공 단어 회상에서도 쓰기와 읽기를 함께 학습한 모델은 우연 수준에 머물렀다.

다만 정확한 과거 단어를 prefix로 직접 주는 읽기 경로를 따로 학습하면 93.75%를 맞혔다. 따라서 이 인터페이스가 정보를 이용하는 것 자체는 가능하다. 실제 대화에서 그 정보를 상태에 쓰고 나중까지 전달하는 공동학습이 이번에 막힌 지점이다.

이 결과는 “대화만으로 기억 특징을 학습할 수 없다”는 일반적 반증이 아니다. 아주 짧은 prefix·적은 학습량·제한된 파라미터 갱신으로 수행한 구현의 실패다. 자동 저장·망각·반환 타이밍·텍스트 기억 출력까지 완성한 모델도 아니다.

## 구현과 검사

- [[메모리-연구/neural-memory/neural-memory/STREAM_MEMORY_SPEC|설계]]
- 모델 (`neural_memory/stream_recurrent_memory.py`; 원 저장소의 파일 참조): 빈 `M0`, 읽기/쓰기 기억 위치, 인과적 텍스트 attention, 구간 간 KV cache 없음.
- 사람 대화 실행기 (`run_stream_recurrent_memory.py`; 원 저장소의 파일 참조): 중요도·근거·구간 제거 라벨, 교사 증류, contrastive 학습 없음.
- 대조 실행기 (`run_stream_memory_control.py`; 원 저장소의 파일 참조): 인공 단일 사실 과제로 읽기 가능성과 학습 경로를 확인.
- 초기 기억은 8×576개의 0, 대화별 float32 약 18 KiB. 독립 대화 사이에 초기화하고 구간 사이에 전달한다.
- 고정 SmolLM2-135M-Instruct + Q/V 저차원 갱신(rank 4) + 기억 projection, 학습 파라미터 562,176개. RMT 원리를 따른 계산 절감 변형이지 원 논문의 전체 학습 재현은 아니다.
- 빈 기억과 메모리 없는 동일 모델의 hidden 일치, 미래 토큰 인과성, padding 불변성, 구간 경계 target 누락/중복 없음, 뒤 손실의 앞 기억 역전파, 고정 출력 헤드 무기울기 등을 검사했다.
- eager 및 실제 실행에 사용하는 SDPA backend에서 인과성·빈 기억 검사를 수행했다. padding에 따라 쓰기 위치가 달라지는 문제를 발견해 rotary position을 보정했다.
- 실제 GPU 실행은 Apple MPS/float32. 최신 전체 검사 **451 passed, 1 기존 경고**.

## 사람 대화 파일럿

MSC의 사람 대화를 학습(train) 256쌍, 검증(valid) 64쌍, 시험(test) 96쌍으로 나눴다. 각 대화의 앞부분만 시간순으로 최대 379토큰 읽는다. 64토큰 구간 6개를 사용하되, 구간 경계의 예측 대상이 빠지지 않게 이미 본 토큰 1개를 겹친다.

모든 대화가 길이 제한으로 잘렸다. 따라서 완전한 다중 세션이나 장기 기억을 검증한 실험으로 해석할 수 없다.

학습 정답은 화자·세션 표식을 뺀 **모든 대화 내용의 다음 토큰**이다. next-token cross entropy는 실제 다음 토큰에 높은 확률을 주도록 하는 손실이다. 구간 사이의 기억을 detach하지 않아 뒤의 손실이 앞선 저장까지 학습시킨다.

200스텝, batch 2, AdamW lr 0.0003으로 학습했다. 검증에서는 `min(빈−자기, 교환−자기)`가 가장 큰 체크포인트를 고른다. 빈 상태와 다른 대화 상태 중 어느 쪽과 비교해도 자기 상태가 유리해야 선택 점수가 높아진다. 아래 NLL은 첫 구간을 제외한 미래 구간 내용의 대화별 평균이며, 손실이므로 낮을수록 좋다.

| seed | 선택 스텝 | 자기 NLL | 빈 NLL | 교환 NLL | 빈−자기 | 교환−자기, 95% CI |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 7 | 50 | 3.50154 | 3.59758 | 3.49791 | +0.09604 | −0.00363 [−0.01858, +0.01138] |
| 17 | 200 | 3.48602 | 3.49109 | 3.48643 | +0.00507 | +0.00041 [−0.00062, +0.00150] |

seed 7은 기억이 아예 없는 것보다는 나았지만, 그 기억이 자기 것인지 타인 것인지는 구별하지 못했다. seed 17은 빈 기억 대비 이득도 작았다. 두 경우 모두 대화별 기억 성공 기준을 통과하지 못했다.

상태 간 cosine 유사도는 각각 0.8602, 0.9969였다. 이 값은 상태의 수치적 방향이 얼마나 비슷한지 보여 준다. 상태가 다르다는 것만으로 필요한 내용이 보존됐다고 말할 수는 없다.

학습 안정성에도 점검할 신호가 있었다. 첫 배치의 기억 projection gradient norm은 제한하기 전 약 5.4천, 533만이었다. 기울기의 크기를 나타내는 값으로, 둘 다 유한했으며 실제 갱신 전에 norm 1로 clipping했다.

큰 기울기가 반복해서 이어지는 기억 경로를 불안정하게 만들 수 있으므로 추가 점검이 필요하다. 다만 한 배치의 관측만으로 gradient explosion이 유일한 실패 원인이라고 확정하지 않는다.

seed 7 선택 자료의 원시 ID 기준 train/valid 및 train/test 교집합은 없었다. 기존 MSC test는 이전 연구에서 반복 확인한 자료이며, swap donor 의존성을 전부 재표집하지 않은 대화별 bootstrap이므로 탐색적 결과다.

## 같은 경로의 인공 단어 회상 대조

사람 대화보다 조건을 단순하게 만들어 같은 경로를 다시 검사했다. 과거에 임의의 비밀 단어를 말하고 잡담 뒤에 그 단어를 묻는다. 정답 후보는 8개다. 한 대조 블록에서는 잡담·질문·사실 위치를 같게 두고 단어만 바꾼다. 질문 모양에서 답을 추측하는 것을 막기 위해서다. 기억할 원래 사실(source fact)이 마지막 구간 원문에는 없다는 것도 검사한다.

자료는 train 8블록/64사례, valid 4블록/32사례, test 12블록/96사례다. 학습 잡담은 2·4·8턴, 시험은 8·16턴이며 동일한 추가 잡담을 붙인다. 32토큰 구간, batch 2, 400스텝, lr 0.0003으로 학습했다.

| 학습 경로 | 선택 스텝 | 자기 상태 정답률 | 빈 상태 | 교환 상태 |
| --- | ---: | ---: | ---: | ---: |
| 모든 대화 내용 손실, 쓰기·읽기 공동학습 | 250 | 12.50% | 12.50% | 12.50% |
| 마지막 미래 구간 내용 손실, 쓰기·읽기 공동학습 | 350 | 12.50% | 12.50% | 12.50% |

두 번째 조건은 손실을 마지막 미래 구간에만 주었다. 앞부분의 사실을 ‘중요하다’고 표시한 것이 아니라, 앞부분을 읽은 뒤 실제로 이어지는 내용을 예측하도록 한 것이다. source/answer annotation을 바꿔도 non-oracle 학습 손실이 그대로인지 검사했다.

모든 내용 토큰을 학습한 경우와 마지막 구간만 학습한 경우 모두 쓰기·읽기를 함께 배우지 못했다. 따라서 ‘전체 토큰 평균에 기억 신호가 희석된 탓’이라는 설명 하나로 실패를 확정할 수도 없다.

읽기 통로 자체를 검사할 때는 **읽기 오라클 학습**을 따로 했다. 이미 관측한 과거 단어의 모델 내부 입력 상태를 memory prefix에 반복해서 넣고, 마지막 구간 손실로 읽기 파라미터를 학습했다.

미래 단어를 미리 주는 것은 아니다. 그러나 어느 과거 위치가 정답 근거인지 안다는 특권이 있으므로 **진단용 경로**다. 이 결과를 학습된 쓰기나 원시 대화 기억 알고리즘의 성능으로 볼 수는 없다.

| 진단 경로 | valid 정답률 | test 정답률 | test 정답 NLL |
| --- | ---: | ---: | ---: |
| 과거 단어 prefix 오라클, 읽기 학습 | 100% | 93.75% | 2.28081 |

정답률은 8지선다 기준, NLL은 전체 LM 어휘 기준이다. 장문 잡담 조건에서 6개를 틀렸고 일부 높은 확신의 오답 때문에 평균 NLL이 높다. 자유 텍스트 생성 정확도는 측정하지 않았다. 오라클은 한 사실을 모든 슬롯에 반복하므로 복수 사실 중 적절한 기억 선택을 검증하지도 않는다.

여기서 결론을 과도하게 넓히면 안 된다. 오라클과 공동학습 모델은 **읽기 구조는 같지만 학습된 파라미터가 다르다.** 따라서 ‘쓰기만 고장이고 읽기는 이미 완벽하다’고 두 부분의 원인을 완전히 분리한 결과는 아니다. 확인된 것은 같은 인터페이스로 읽기가 가능하다는 점과, 이번 공동학습 경로는 실패했다는 점이다.

초기 오라클 실행에는 checkpoint를 실제 학습한 오라클 경로가 아니라 자기 상태 NLL로 고르는 오류가 있었다. 경로에 맞는 검증값으로 수정하고 검사와 전체 400스텝 재실행을 수행했다. 위 수치는 `selection-fixed` 파일만 사용한다. 기존 오류 실행은 기록을 보존했지만 판정에서 제외한다.

## 다음의 좁은 검증

다음에는 사람 대화의 평균 예측 학습부터 더 늘리지 않는다. 먼저 이 작은 회상 과제에서 기억 갱신이 학습되는 조건을 나눠 검사한다.

직접 넣은 오라클 상태와 writer가 만든 순환 상태의 분포가 얼마나 다른지, 역전파가 이어지는 구간 수에 따라 기울기가 얼마나 커지는지, 초기 쓰기 위치와 상태 projection의 학습이 안정적인지 확인한다. 현재는 읽기와 쓰기가 파라미터를 공유하므로 한쪽을 바꾸면 다른 쪽도 바뀌는 결합을 함께 고려해야 한다.

그 이후에만 더 긴 원시 대화, 사실 수정·여러 사실·불필요한 반환 억제, 실제 기억 내용 텍스트 출력으로 확장한다. “대화로 기억 특징이 학습될 수 있다”는 가설은 유지하지만, 이번 구현이 그 가설을 실현했다고 말하지 않는다.

