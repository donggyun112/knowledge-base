# 어휘 전이·경쟁 잡담·정정 검사 — 2026-09-27

## 결론

**기억 경로는 학습한 8개 정답 밖으로 일반화하지 못했다.** 읽기 고정/공동학습과 seed 7/17을 조합한 네 모델 모두 새 단어의 중립 시험에서 전체 어휘 정답률이 0/64였다. 새 단어를 사용한 여섯 시나리오 전체에서도 각각 0/384였다.

이 결과는 앞선 긴 잡담 시험의 100%를 해석하는 범위를 좁힌다. 알려진 단어를 기억하는 데는 성공했지만, 임의의 단어를 다루는 범용 기억 모델의 성공으로 볼 수는 없다.

문제가 단어를 읽는 능력 자체에 있는지 확인하려고, 같은 가중치의 읽기 모델에 과거 원문 전체를 직접 제공했다. 그러자 seed 17의 두 모델은 같은 새 단어를 64/64 맞혔다.

따라서 새로운 단어를 원문에서 읽는 능력이 전혀 없는 것은 아니다. 실패는 원문에서 정보를 얻어 잠재 기억으로 전달하고 그 상태를 읽는 경로의 일반화에 있다. 다만 이번 검사로 쓰기·보존·잠재 상태 읽기 중 어느 하나를 단독 원인으로 확정할 수는 없다.

후속 [[메모리-연구/neural-memory/neural-memory/STREAM_MEMORY_OPEN_VOCAB_REPORT|값 다양성 대조]]에서는 같은 구조에서 학습 값을 256개로 늘려 별도 64개 값의 전이가 50.00~54.69%로 개선됐다. 이 문서의 실패 결과는 이전 8값 학습 모델에 대한 기록으로 유지한다. 정정 실패는 후속 실험에도 남아 있다.

## 고정한 조건

- 기존 `stream-rmt-control-acquire-{frozen,joint}-seed{7,17}.pt`를 수정 없이 평가했다. 추가 학습 0스텝, Apple MPS/float32. 완료 후 네 adapter가 저장 파일과 정확히 같은지 확인했다.
- 메모리 학습 정답: apple, moon, glass, dog, river, chair, green, stone.
- 새 정답: cat, sun, paper, bird, ocean, table, blue, cloud. **메모리 추가 학습의 정답 어휘에서 미사용**이라는 뜻이지 LM 사전학습에서 미사용이라는 뜻은 아니다. 이 목록은 GPU 성능을 보기 전에 선택하고 실제 토크나이저로 검증했다.
- 각 조건은 같은 잡담 seed 4009, 8개의 독립 잡담 블록 × 8개 답 = 64사례. 기본 잡담 8/16턴을 번갈아 사용하고, 원래 평가와 같은 뒤 잡담 3턴을 더했다.
- 2개 어휘 집합 × 6개 시나리오 × 4개 모델, 총 3,072사례. 신뢰구간은 독립 사례 수가 아니라 **8개 잡담 블록**을 재표집한다.
- 같은 블록의 8개 원문은 과거 정답 근거 토큰과 최종 정답 토큰 두 곳만 다르다. 잡담·간섭·질문은 답에 따라 바꾸지 않는다. 정답 근거가 마지막 원문 창 밖에 있는지 검사한다.
- 어휘·블록·원문 토큰 SHA-256·근거/정답 위치가 일치해야 모델끼리 비교한다. 마지막 미래 정답 토큰을 바꿔도 메모리 평가의 예측이 같다는 회귀 검사도 통과했다.

검사 시나리오는 다음과 같다.

| 이름 | 사실 이후 추가 내용 |
| --- | --- |
| neutral | 기존 생성기 그대로의 중립 잡담 |
| mentions_neutral | `Friend: The word topic appeared in the book I read.` 8회 |
| mentions | 위 문장의 topic 대신 8개 정답 후보를 각 1회 언급 |
| other_fact_neutral | `Friend: My secret word is clock.` 8회 |
| other_fact | 위 문장의 clock 대신 8개 정답 후보를 각 1회 언급 |
| correction | 앞서 `Me: My secret word is clock.`을 말하고, 새 근거를 `Me: Actually, my secret word is ...`로 정정 |

mentions/other_fact에서는 후보 순서를 블록마다 무작위로 정하되, 같은 블록의 모든 정답에 동일한 순서를 적용했다. 짝지은 neutral 대조와 비교해 토큰 길이, 사실/정답 위치, 마지막 질문 창이 실제 토크나이저에서도 같은지 확인했다.

other_fact는 다른 화자의 사실이 본인 기억을 방해하는지 보는 검사다. 여러 속성을 각각 질문하는 본격적인 다중 사실 벤치마크는 아니다. correction에서는 고정된 옛 단어와 새로운 정정 문장 형식을 함께 바꿨으므로 두 요소의 효과를 분리하지 않는다.

아래 지표는 전체 어휘 중 확률이 가장 높은 단일 토큰을 골랐을 때의 정확도다. 학습한 단어를 사용한 이 조건에서는 8지선다 정확도도 같은 값이었다.

| 시나리오 | 고정 7 | 공동 7 | 고정 17 | 공동 17 |
| --- | ---: | ---: | ---: | ---: |
| neutral | 100% | 100% | 100% | 100% |
| mentions_neutral | 100% | 100% | 100% | 100% |
| mentions | 90.63% | 65.63% | 76.56% | 95.31% |
| other_fact_neutral | 96.88% | 76.56% | 65.63% | 92.19% |
| other_fact | 73.44% | 56.25% | 68.75% | 76.56% |
| correction | 93.75% | 100% | 79.69% | 54.69% |

단어 자체의 간섭을 분리하려고 mentions를 짝지은 대조와 비교했다. 후보를 언급한 점수에서 topic을 언급한 점수를 뺀 변화는 고정 7: −9.38%p, 공동 7: −34.38%p, 고정 17: −23.44%p, 공동 17: −4.69%p였다.

짝지은 블록 부트스트랩의 95% 구간은 각각 [−15.63, −4.69], [−53.13, −15.63], [−45.31, −6.25], [−10.94, 0]%p였다. 세 모델의 하락 구간은 0을 포함하지 않지만 공동 17의 정확도 변화는 불확실하다. 8블록의 탐색적 비교이며 다중 비교 보정은 하지 않았다.

other_fact에서는 후보를 넣기 전, clock만 반복한 대조에서도 일부 모델의 성능이 낮아졌다. 고정 17은 후보 단어로 바꿨을 때 추가로 악화되지 않았다(65.63% → 68.75%, 짝지은 구간에 0 포함). 따라서 다른 화자의 사실을 전반적으로 안정되게 구분한다고 할 수는 없다. 동시에 모든 seed가 같은 간섭 양상을 보인다고 일반화하지도 않는다.

빈 기억의 8지선다 정확도는 모두 12.50%였다. 새 정답 8개로 **출력 후보를 강제로 제한**하면 일부 정보는 구분하지만, 전체 어휘에서 자유롭게 답 토큰을 고르면 정답이 전혀 나오지 않았다. 기억이 완전히 무정보 상태라고 단정할 수는 없지만 새 단어를 제대로 출력하는 데는 실패한 것이다. 정답 NLL도 네 모델 모두 빈 기억보다 나빠 현재 상태가 정상적인 새 단어 예측에 도움이 됐다고 평가할 수 없다.

새 단어 조건 전체 1,536사례에서 확률이 가장 높은 출력 토큰은 모두 기존 8개 학습 단어 중 하나였다. 이는 **8개 값에 맞춘 코드북이나 분류기처럼 행동한다는 해석**과 맞는다. 다만 내부 표현 자체가 실제로 8개의 이산 코드로만 구성된다는 것을 증명한 결과는 아니다.

공동 17의 첫 중립 블록에서 실제 출력은 다음과 같았다. 모든 사례는 같은 잡담과 질문이며 과거 사실의 단어만 바뀐다.

## 원문 직접 읽기 대조

원문 직접 읽기에서는 기억을 거치지 않고 **실제 과거 원문 전부**를 같은 Q/V 어댑터의 Transformer에 한 번에 넣었다. 마지막 답 직전에서 예측하며 미래 정답 토큰은 입력에서 완전히 제외했다.

이 대조의 목적은 반복적인 기억 압축을 건너뛰었을 때 읽을 수 있는 정보의 상한을 확인하는 것이다. 실제로 제안하는 기억 구조로 사용한 것은 아니다.

| 새 단어, 같은 긴 원문 | 고정 7 | 공동 7 | 고정 17 | 공동 17 |
| --- | ---: | ---: | ---: | ---: |
| 기억 경로: 전체 어휘 정확도 | 0% | 0% | 0% | 0% |
| 원문 직접 읽기: 8지선다 | 100% | 100% | 100% | 100% |
| 원문 직접 읽기: 전체 어휘 정확도 | 14.06% | 57.81% | 100% | 100% |
| 원문 직접 읽기: 대소문자만 무시한 단어 일치 | 100% | 100% | 100% | 100% |

seed 7의 원문 직접 읽기에서 오답으로 집계된 것은 Cat/Sun 같은 대문자 토큰이었다. 이를 구분하기 위해 **결과를 본 뒤 대소문자 무시 진단을 추가**했다. 이 보조 지표가 기본인 전체 어휘 단일 토큰 정확도를 대체하지는 않는다. 짧은 `Me: My secret word is ...` 원문과 질문으로 비교하면 네 어댑터 모두 새 8개 단어를 소문자 정답 그대로 맞혔다(8/8, 단일 템플릿).

어댑터를 붙이지 않은 원래 사전학습 LM도 함께 검사했다. 원문을 직접 주면 새 단어의 8지선다는 100%였지만 전체 어휘 정확도는 0%였다. 답으로 My/It을 먼저 내거나 대문자 토큰을 고르는 경향 때문이었다. 그러므로 원래 LM의 자유 출력 능력이 100%라는 주장은 근거로 삼지 않는다.

판단의 핵심은 **같은 학습 가중치에 같은 원문을 제공한 대조**다. seed 17은 원문을 직접 읽으면 100%, 기억 경로를 거치면 0%였다.

## 해석과 다음 실험

이번에 확인한 실패는 학습 어휘 밖의 단어를 기억하는 능력과 경쟁 잡담에 대한 내성이다. 학습에는 8개 정답, 규칙적인 사실 문장, 정답과 경쟁하지 않는 잡담만 있었다. 따라서 이 좁은 분포에서 미래 예측 손실을 줄이는 데 특화된 경로를 배웠을 가능성을 우선 의심한다.

**이는 학습 분포에 대한 가설**이다. 학습 값을 다양화한 조건이나 구조를 바꾼 조건을 실제로 비교하기 전에는 실패 원인으로 확정하지 않는다.

다음 실험은 구조와 손실을 유지한 채 정답 값의 다양성만 늘리는 대조다. 수백 개의 단일 토큰 값을 학습에 쓰고 검증·시험의 정답 어휘를 서로 분리해, 학습하지 않은 값까지 기억이 전이되는지 먼저 확인한다. 이를 위해 저장 중요도나 저장/검색 도구 라벨을 추가할 이유는 없다.

이 좁은 전이를 통과하지 못한다면 사람 대화로 규모만 키우거나 긴 잡담의 정확도만 다시 높여도 충분한 검증이 되지 않는다.

그 다음에 다른 화자/다른 속성의 사실, 정정, 경쟁 잡담을 학습과 독립된 형식으로 검사한다. 최종 목표인 사람 대화의 일반적 저장 판단, 여러 사실의 선택적 유지·망각, 기억 텍스트 출력, 자동 반환/침묵은 여전히 구현·검증되지 않았다.

## 구현·검사·재현

- `controls_from_cases`로 기존 토큰화·스트림 처리 경로를 재사용했다. 기존 중립 생성기의 원문과 토큰 범위가 정확히 같다는 회귀 검사를 추가했다.
- 준비 상태와 답별 잡담의 동일성, 후보 토큰의 차이, 마지막 창으로 근거가 누출되지 않는지, 앞선 원문 단어와 정정 근거, 짝지은 조건의 위치가 같은지를 검사했다. 미래 답 토큰을 바꿔도 예측이 같은지, 원문 대조에서 미래 답을 완전히 제외했는지, 잘못된 짝비교를 거부하는지도 확인했다.
- codecanvas 색인에서 새 실험 함수를 찾지 못해 변경 영향을 정적 그래프로 입증하지는 못했다. 대신 기존 경로와의 동등성 및 실제 CPU/GPU 실행으로 확인한 범위를 명시했다.
- 전체 검사에서 **521개가 통과했고 기존 requires-grad scalar 경고 1개**가 남았다. GPU 평가 네 건과 원문 진단은 모두 정상 완료됐으며 체크포인트 가중치는 바뀌지 않았다.
