# ParetoSaddler — 품질과 비용을 함께 보는 하네스 최적화

**최종 배포 조건을 중간 탐색 후보에도 곧바로 적용하면, 이후 개선의 발판이 될 하네스를 너무 일찍 버릴 수 있다.** ParetoSaddler는 후보의 탐색 승격과 최종 배포 선택을 분리하는 오프라인 최적화 방법이다. 모델 가중치와 과제 모델의 추론 설정을 고정하고 프롬프트·스킬·도구 코드·실행 제어를 수정한다.

> [!info] 자료와 검토 상태
> Xingzhi Qian 외, *ParetoSaddler: Pareto-Guided Optimization of Agent Harnesses for Quality and Cost*. arXiv v1 제출 **2026-11-01 UTC**, 수집 **2026-11-04 KST**. 본문·부록에 근거한 요약이며 실행·재현·실서비스 검증은 하지 않았다. **Techniques / Assess · 읽기 전**. 아래 효과는 저자 보고이며 다른 하네스의 채택 근거로 곧바로 전환하지 않는다.

## 1. 무엇을 반복해서 개선하는가

[방법과 알고리즘](https://arxiv.org/html/2611.02079v1#S4)은 AutoSaddler의 최적화 상태와 EvoDAG를 확장한다.

1. 초기 하네스를 개발 과제에서 평가한다.
2. 보통 훈련 과제 3개를 각각 3회 실행해 부모 하네스의 품질·비용·실행 기록을 모은다.
3. 별도의 최적화 에이전트가 코드와 실행 기록을 보고 패치를 만든다. 실패뿐 아니라 **성공했지만 비용이 큰 실행**도 개선 대상이다.
4. 같은 과제에서 후보를 반복 실행한다. 호환되는 부모 실행 결과는 재사용한다.
5. 반복 관측값으로 Bayesian bootstrap을 수행해 개선 지지를 추정한다. 통과한 후보만 더 넓은 개발셋에서 평가한다.
6. 개발 평가를 받은 후보 전체와 별도의 비지배 후보 집합을 유지한다. 현재 지배되는 후보도 이후 패치의 재료가 될 수 있다.
7. 탐색 예산이 끝나면 개발셋의 품질–비용 전선이나 품질 하한을 만족하는 최소비용 후보를 선택한다. 테스트셋은 최종 평가에 사용한다.

배포 선호가 부모 구성에는 영향을 줄 수 있지만, 중간 후보를 최종 선호만으로 제거하는 것과는 구분한다. 실시간 운영 중 스스로 코드를 바꾸는 온라인 자기개선 시스템을 검증한 논문은 아니다.

## 2. 이름과 달리 엄격한 파레토 우월성만 요구하지 않는다

실험의 승격 기준은 부모 대비 다음 둘 중 하나다.

- 품질이 개선된다. **이때 국소 비용 증가의 상한은 두지 않는다.**
- 비용이 감소하고 품질 하락이 **10%p 이내**다.

과제별 각 하네스의 3회 관측에 Dirichlet 가중치를 독립적으로 뽑고, 동일 실행의 품질·비용에는 같은 가중치를 적용해 연관성을 보존한다. 과제는 같은 비중으로 평균한다. **10,000회 bootstrap 중 70% 이상이 위 조건을 지지하면 승격**한다. 이는 기존 결과의 재가중 계산으로 추가 LLM 호출은 없다.

이 70%를 보편적인 성공 확률이나 새 과제 일반화 확률로 읽으면 안 된다. 고정된 소수 과제에서 관측한 실행 변동을 다루며, 과제 표본 자체의 불확실성은 포괄하지 않는다. PS-MinCost의 최종 품질 하한도 초기 하네스보다 최대 10%p 낮을 수 있다. 중간 승격과 최종 선택 모두 무손실 개선 보장이 아니다.

## 3. 실제 패치의 범위

[ClawMark 사례](https://arxiv.org/html/2611.02079v1#A9)와 [GAIA2 사례](https://arxiv.org/html/2611.02079v1#A10)는 단순한 프롬프트 길이 조절을 넘는다.

- 도구 전체 스키마를 반복 출력하지 않고 필요한 정보만 탐색한다.
- 메일의 필터·헤더 위주 조회와 연락처 일괄 조회로 읽기·호출량을 줄인다.
- 캘린더 검색 범위를 제한하고 전사 작업의 대기·실패 탐색을 제한한다.
- 필요한 결과물을 먼저 작성하고, 종료 처리와 도구 실행 전 모호성 검사를 조정한다.
- ClawMark PS-Pareto 대표 후보는 6개 파일, GAIA2 대표 후보는 13개 파일을 변경했다. 별도 ClawMark MinCost 후보는 실행 가능한 출력 압축 등 15개 파일을 변경했다.

프롬프트 지침과 코드로 강제한 동작은 다르다. 여러 변경이 함께 적용된 사례이므로 개별 패치 하나가 전체 효과의 원인이라고 단정할 수 없다. 일부 MinCost 안내에는 구현되지 않은 도구 참조도 있었다고 부록이 밝힌다.

## 4. 비교 조건과 결과

[실험 상세](https://arxiv.org/html/2611.02079v1#A1): 시나리오·universe가 겹치지 않도록 훈련/개발/테스트를 나눈다.

| 조건 | ClawMark | GAIA2 |
| --- | --- | --- |
| 훈련 / 개발 / 테스트 과제 수 | 50 / 20 / 22 | 75 / 65 / 300 |
| 과제 하네스 | OpenClaw v2026.6.9 | 기본 ReAct 방식 |
| 과제 모델 | GPT-5.4, high | GPT-5.5, medium |
| 품질 지표 | 정규화한 stage-0 rubric 점수 | Pass@1 |
| 반복 | 과제당 3회 | 과제당 3회 |

최적화 모델은 모든 방법에서 GitHub Copilot SDK를 통한 GPT-5.5, xhigh다. ClawMark는 초기 stage만 다루며 후속 단계 적응을 평가하지 않는다. 비교군 AutoSaddler와 Meta-Harness는 이 실험 목적에 맞춘 변형이며, 원 구현을 그대로 실행한 동일 예산 비교가 아니다. PS/AS는 각각 17·25회 제안, Meta-Harness는 더 큰 검색 집합에서 8·15회 제안한다.

[표 1](https://arxiv.org/html/2611.02079v1#S5.T1)의 평균값을 옮겼다. 비용은 **과제 실행 모델의 토큰 기반 USD/과제**다. ClawMark 점수를 과제 성공률로 부르지 않는다.

| 방법 | ClawMark 품질 / 비용 | GAIA2 품질 / 비용 |
| --- | --- | --- |
| 기본 하네스 | 70.86 / \$1.17 | 56.22 / \$0.78 |
| AutoSaddler Quality | 73.86 / \$1.24 | 57.33 / \$0.61 |
| Meta-Harness Pareto 품질 끝점 | 73.25 / \$1.06 | 54.33 / \$0.83 |
| Meta-Harness Pareto 비용 끝점 | 70.50 / \$0.97 | 55.44 / \$0.80 |
| Meta-Harness MinCost | 70.02 / \$1.16 | 39.78 / \$0.62 |
| ParetoSaddler Pareto 품질 끝점 | **81.35 / \$1.01** | **62.89 / \$0.45** |
| ParetoSaddler Pareto 비용 끝점 | 79.60 / \$0.92 | 62.11 / \$0.47 |
| ParetoSaddler MinCost | 75.16 / \$0.82 | 56.11 / \$0.44 |

품질 끝점은 기본 대비 ClawMark **+10.49%p·비용 −13.7%**, GAIA2 **+6.67%p·비용 −42.3%**다. 원문은 고정된 최종 하네스의 3회 테스트 반복에 대한 표본 표준편차도 보고한다. 이는 여러 독립 최적화 시드의 분산이 아니다. 대표 품질 끝점의 품질 표준편차는 각각 3.11·2.14%p, 비용 표준편차는 모두 \$0.02다.

끝점은 개발셋에서 정하므로 테스트에서 비용 순서가 뒤집힐 수 있다. 실제 GAIA2에서는 품질 끝점이 비용 끝점보다 싸다. 추가 GAIA2 독립 최적화 실행에서도 비슷한 범위를 보고하지만, 모든 방법·조건을 충분한 시드로 반복한 연구는 아니다.

## 5. 실행 비용 절감과 최적화 총비용은 별개다

토큰 비용은 새 입력·캐시 입력·출력을 구분하고 첫 유효 호출을 cold-start 가격으로 정규화한다. 지연시간, 인프라, 유지보수까지 포함한 전체 운영비 절감은 아니다.

- PS/AS의 최대 과제 실행 예산은 초기 평가 포함 ClawMark **1,380회**, GAIA2 **5,520회**다. 실제 실행 수는 후보 승격 수에 따라 달라진다.
- Meta-Harness의 최대 예산은 각각 **1,890회·6,720회**다. 프로토콜과 계산 예산이 동일하지 않다.
- [부록 G](https://arxiv.org/html/2611.02079v1#A7)의 GAIA2 PS-Pareto 최적화 모델 비용은 패치당 평균 **\$9.62**, 25회다. 단순 곱으로 약 **\$240.50**이며, **과제 평가 모델의 수천 회 실행 비용은 별도**다.
- 최적화 모델은 패치당 평균 982초, 86.6회 LLM 호출을 사용했다. 이 값은 최종 하네스의 과제당 지연시간이 아니다.
- 논문은 전체 최적화 달러 비용 합계나 실제 배포량별 손익분기를 제공하지 않는다.

따라서 \$0.78에서 \$0.45로 줄었다는 결과만으로 전체 비용이 감소했다고 결론 내리지 않는다. 별도 검토에서는 최초 최적화·재최적화·평가 비용을 누적 실행 절감액과 비교해야 한다.

## 6. 검증 범위와 활용 질문

**저자 실험의 한계:** 두 벤치마크와 특정 모델·하네스 조합, 작은 ClawMark 테스트셋, 과제당 3회 관측, 과제 표본 불확실성 미포함, 제한된 독립 최적화 반복이다. 안전성·공정성·무해성·실사용자 개인정보 보호는 평가하지 않았다. 반복 실행을 늘린 절제 실험도 계산량을 맞춘 비교는 아니다. [한계](https://arxiv.org/html/2611.02079v1#A12)

**이 노트의 해석:** 참고할 대상은 특정 패치나 임계값의 무조건 적용이 아니라, 품질·비용을 따로 기록하고 중간 탐색과 배포 판단을 분리하는 평가 방법이다. 다음은 아직 실행하지 않은 검토·작은 실험 제안이다.

1. 소수의 재현 가능한 과제로 기준 하네스의 반복 실행 분산과 실제 모델 비용을 먼저 측정한다. 최적화용 문제와 최종 평가용 문제를 분리한다.
2. 수정 가능한 파일과 금지할 변경을 정한다. 성공률을 위해 승인·권한·검증을 제거하는 패치는 별도의 회귀 검사로 막는다.
3. 동일 후보 기록에서 품질 전용·평균값·bootstrap 승격의 선택 차이를 비교한다. 비교 예산 차이를 함께 공개한다.
4. 최종 후보는 품질·비용뿐 아니라 실패 유형, 지연, 권한 위반을 평가한다. 비싼 성공이 실제로 불필요한 호출 때문인지도 확인한다.
5. 최적화 총비용과 예상 재사용 횟수를 연결한다. 도구·모델 변경 뒤 재최적화 비용까지 포함해 투자 회수를 판단한다.

직접 실행하거나 채택한 근거가 없어 **Assess / 읽기 전**을 유지한다.
