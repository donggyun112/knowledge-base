# OpticalRAG — 시각 토큰 압축과 전체 비용의 구분

- **원문**: [논문 v1](https://arxiv.org/abs/2611.13675v1) · [본문·부록](https://arxiv.org/html/2611.13675v1)
- **확인된 발행일**: 2026-11-10 (v1). 이후 개정은 검토 범위 밖이다.
- **수집일**: 2026-11-14 KST
- **상태**: Techniques / Assess / 읽기 전
- **검증 범위**: 공개 원문 정적 검토. 학습·모델 호출·재현 실험은 하지 않았다.

## 원문 핵심

문서 텍스트를 이미지로 렌더링하고, 고정 비전 인코더가 만든 시각 토큰을 색인한다. 질의 표현을 같은 공간으로 투영해 검색한 뒤, 질문 조건부 압축기와 브리지가 결과를 **16개 연속 벡터 prefix**로 바꿔 LLM에 주입한다. 읽을 수 있는 16단어 요약이 아니다. 압축기와 브리지는 학습하며 인코더·LLM은 고정한다. [§4, 부록 D.7](https://arxiv.org/html/2611.13675v1#S4)

## 결과와 한계

- LongBench-v2 점수는 일반 RAG 31.41, OpticalRAG 35.79지만, BAMBOO에서는 각각 69.50, 61.00이다. 세 벤치마크 최고라는 CAP는 정확도에 압축 보상을 합친 지표이며 순수 정확도가 아니다.
- 평가 중심은 객관식이다. **선택지가 검색·압축 입력에도 포함**되며, 16토큰에는 질문·선택지·지시문이 포함되지 않는다.
- 일반 RAG 비교군은 BM25 방식이다. 질문만 받는 hybrid 검색·reranker를 대체한다는 근거는 아니다.
- 렌더링·인코딩·색인·학습·질의 압축까지 포함한 총운영비 절감으로 해석할 수 없다. 자유형 답변·정밀 인용은 별도 검증 대상이다. [§6–7, 부록 C.2·D.8](https://arxiv.org/html/2611.13675v1#S6)

## 활용 맥락과 작은 검증 제안

아래는 미실행 제안이다. 검색 품질과 LLM에 전달하는 표현을 분리해서 판단할 때 참고한다.

1. 같은 공개 문서·검색 후보에서 원문 전달과 압축 표현을 비교한다. 선택지는 숨기고 질문만 입력한다.
2. 정확한 답, 근거 위치, 숫자·식별자 보존을 각각 채점한다. 압축률만 최적화하지 않는다.
3. 초기 학습·색인과 갱신 비용, 질의당 전체 지연·메모리·비용을 분리한다. 반복 질의량별 손익을 계산한다.
