# NAVER Care AI — 과거 장애는 후보, 현재 상태는 판정 근거

**같은 증상이 같은 원인을 뜻하지 않는다.** 과거 장애는 무엇을 조사할지 좁히는 데 쓰고, 이번 장애의 원인이라고 답하려면 현재 상태에 근거가 있어야 한다.

- **원문**: NAVER D2 [1부: RCA·Q&A 운영 지식그래프](https://d2.naver.com/helloworld/6934862), [2부: MCP부터 Agent 설계까지](https://d2.naver.com/helloworld/5073599)

- **수집일**: 2026-11-27 KST

## 1. 사례 찾기와 현재 원인 판정

1부는 실제 OpenSearch 업그레이드 지연 문의를 따라간다. 과거 n3r 운영 문의에서 근본 원인 분석(RCA)과 Q&A를 추출해 Neo4j에 저장하고, 하이브리드 검색과 LLM 리랭킹에 클러스터 상태를 활용해 증상뿐 아니라 원인도 비슷한 사례를 찾는 구조다. 공개 요약만으로 그래프, 하이브리드 검색, 리랭킹, 상태 조회 각각의 기여를 분리할 수는 없다.

2부에서는 모델이 조사하고 판단할 후보를 좁히되, 근거 검증과 최종 판정은 코드가 맡도록 바꿨다. 같은 문의를 세 번씩 평가한 결과, 정확한 원인을 답한 횟수가 0/3에서 3/3으로 늘었다고 한다. 이는 **한 문의의 반복 평가**다. 서로 다른 세 장애에서 성공했다거나 전체 진단률이 개선됐다고 읽을 수 없다.

## 2. 도구 응답을 작게 만든 결과는 별개다

별도의 변경으로 MCP 도구의 응답을 요약 우선으로 바꾸고, 원본은 필요할 때만 요청하게 했다. 팀이 보고한 24회 평가에서는 정답이 10회에서 17회로 늘고 토큰 사용량이 26% 줄었다. 이 수치는 요약 우선 변경의 내부 평가이며, 코드 판정 변경의 성과로 합산하면 안 된다. 공개 요약만으로 추가 원본 조회 횟수, 전체 지연, 증거 누락률, 다른 장애군에서의 효과는 알 수 없다.

## 3. 다음에 확인할 작은 테스트

같은 문의 문구와 과거 사례 후보를 두고, 읽기 전용 현재 상태만 바꾼 합성 티켓 두 건을 만든다. 실제 원인은 서로 다르게 두고, 세 번째 티켓에서는 현재 상태를 숨기거나 오래된 상태만 제공한다. 모델, 후보 및 컨텍스트 예산을 맞춰 과거 사례만 쓴 경우와 현재 상태를 함께 준 경우를 비교한다. **모델 후보의 정답률**과 **검증기가 확정한 원인의 정확도·판정 보류율**은 따로 기록한다. 현재 대상과 시간 범위에 맞는 근거가 없으면 모름을 반환하고, 다른 클러스터의 유사 증거로 판정하지 않는 것을 목표로 삼는다. 이는 검증 제안이지 Care AI가 공개적으로 보장한 동작이 아니다.
