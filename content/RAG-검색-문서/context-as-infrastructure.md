# Context as Infrastructure — 검색과 읽기 비용을 분리하기

## 원문 핵심: 찾는 과정과 읽는 표현

전처리에서 glm-4-flash가 청크를 **주장·원문 근거 쌍**으로 변환한다. 근거의 원문 일치를 검사하고 출처·오프셋을 보존한다. 주장은 임베딩하여 군집화하지만, 질의 검색은 BM25/grep이다.

기본 E2 경로는 원문 검색으로 청크를 찾고, 모델에 전달할 때 근거 쌍으로 대체한다. 게이트가 불충분하다고 판단하면 원문을 읽는다. 검색기를 교체하는 실험과 구별해야 한다. [§4.2–4.3](https://arxiv.org/html/2610.41172v1#S4)

## 결과와 해석 한계

FRAMES 200질문에서 질의 전체 토큰은 평균 38% 감소했다. 이는 전처리·갱신을 포함한 운영비 절감률이 아니다. 비용 회수 조건은 모형으로 제시한다.

- Dense 검색을 비교하는 실험 조건은 없다. Dense가 불필요하다는 일반적 결론을 뒷받침하지 않는다.
- 원문 문자열 일치가 주장의 의미적 타당성을 보장하지 않는다. 게이트 수락률도 정답률이 아니다.
- 영어 QA 중심이며 단일 실행의 정확도 비교는 작은 효과를 확정하기 어렵다.
- 지연 비교는 양쪽이 답한 7질문이다. 표현 축소가 검색 회차를 늘려 지연을 악화시킨 경우도 있다. [§8](https://arxiv.org/html/2610.41172v1#S8)

## 활용 맥락과 작은 검증 제안

아래는 이 노트의 해석과 미실행 제안이다. 검색 품질 개선과 전달 컨텍스트 축소를 독립적으로 평가할 때 참고할 수 있다. 현재 시스템에 바로 도입하자는 권고는 아니다.

1. 같은 문서·질의·검색 후보를 고정하고 원문 읽기와 근거 쌍 읽기만 바꾼다. 후보 회수율, 답변 정확도, 인용 타당성, 질의 토큰, 지연을 따로 기록한다.
2. Dense를 사용하는 시스템이라면 유지한 대조군부터 둔다. 가공 유무와 검색 방식의 효과를 섞지 않는다.
3. 생성된 주장에 부정·조건·시간 범위가 보존됐는지 표본을 확인한다. 게이트가 수락했지만 근거가 부족한 경우를 별도로 센다.
4. 최초 가공, 변경 문서 재가공, 저장, 질의 실행을 같은 금액 단위로 합산한다. 예상 질의량과 갱신률을 바꾸며 손익이 뒤집히는 지점을 확인한다.
