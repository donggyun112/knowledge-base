# MCP 보안 경계 — 토큰·동의·세션을 같은 것으로 보지 않기

**MCP 연결이 성공했다는 사실만으로, 특정 사용자가 특정 클라이언트의 특정 작업까지 허용했다는 결론을 내릴 수는 없다.** 이 노트는 MCP 공식 보안 가이드를 바탕으로 인증과 위임 경계를 나누어 읽는다.

> [!info] 조사 기준
> 수집일 **2026-11-02 KST**. 원문 제목은 *Security Best Practices*. 문서 경로의 버전 표기는 **2025-11-25**이며 개별 페이지 발행일은 미표기다. 경로 날짜를 이 노트의 발행일이나 현재 최신 명세라는 뜻으로 사용하지 않는다. **Techniques / Assess · 읽기 전**. 본문 검토만 했고 서버 설치·보안 실험은 하지 않았다.

## 공식 문서에서 읽을 핵심

| 경계 | 핵심 내용 |
| --- | --- |
| 토큰의 대상 | MCP 서버를 위해 발급되지 않은 토큰을 받아 downstream API에 그대로 전달하는 token passthrough는 금지된다 |
| 위임 동의 | 외부 API를 대신 호출하는 MCP 프록시는 사용자별·클라이언트별 동의를 관리해야 한다. 기존 외부 서비스 동의 쿠키가 새 MCP 클라이언트의 동의를 대신하지 않는다 |
| 세션 | 세션 ID를 인증 수단으로 쓰면 안 된다. 인가를 구현한 서버는 모든 inbound 요청을 검증해야 한다. 세션을 인증된 사용자와 결합하는 것도 권고된다 |
| 발견 URL | OAuth 메타데이터 조회도 네트워크 접근이다. 서버 측 클라이언트는 SSRF 위험을 고려하며 리디렉션 목적지와 DNS 검사·사용 시점 차이도 다룬다 |

출처: [공식 보안 가이드](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices). 여기서 요약한 요구사항은 연결 방식과 구현 역할에 맞춰 읽어야 한다. 특정 SDK가 이 조치를 이미 수행한다고 확인한 것은 아니다.

## 설계에 적용한다면: 한 개의 허용 상태 대신 세 질문

아래는 문서의 성능 결과가 아니라 **설계 검토를 위한 해석**이다.

1. **이 요청은 누구에게서 왔는가?** 세션을 찾았다는 사실과 요청 주체를 인증했다는 사실을 별도 항목으로 기록한다.
2. **그 주체가 어떤 위임을 받았는가?** 사용자, MCP 클라이언트, 대상 서비스와 허용 범위를 따로 표현한다. 단일 `connected=true` 값으로 모두 대체하지 않는다.
3. **지금 이 동작을 허용하는가?** 연결·인증·동의가 유효하더라도 작업 인자와 대상 리소스까지 검토하는 경계를 남긴다.

이 구분은 여러 클라이언트가 한 프록시를 공유하거나 세션 저장소를 여러 서버가 공유할 때 특히 검토할 가치가 있다. “어느 단계에서 승인했는지”를 알 수 있어야 오류를 재현하고 권한을 회수하기도 쉽다.

## 작은 검증 제안 — 아직 실행하지 않음

실제 토큰·개인 데이터·외부 서비스 대신 **합성 사용자와 로컬 모형 응답**만 쓰는 테스트 설계를 먼저 만든다.

| 사례 | 확인할 기대 조건 |
| --- | --- |
| 토큰 대상이 다른 요청 | 세션이 있어도 인증 경계를 통과하지 않음 |
| 같은 사용자, 다른 MCP 클라이언트 | 기존 연결 상태만으로 새 클라이언트의 동의를 추정하지 않음 |
| 다른 사용자가 기존 세션 ID를 제시 | 세션 자료가 섞이거나 다른 사용자의 이벤트를 읽지 못함 |
| 인가가 만료된 뒤 세션 재사용 | 복구·재연결 경로에서도 요청 주체와 권한을 다시 확인함 |

먼저 코드 리뷰에서 각 거부를 담당하는 위치와 감사 이벤트를 표시한다. 이후 실험을 하게 되면 정상 요청도 함께 검사해, 모든 요청을 막는 구현이 통과한 것처럼 보이지 않게 한다. 이 표는 완전한 보안 테스트 목록이나 안전성 인증이 아니다.

## 한계와 다음 질문

이 자료는 위협과 대응을 설명하는 가이드이지 특정 배포의 안전성을 입증하는 측정 결과가 아니다. 여기서는 주로 원격 HTTP·프록시의 인증 경계를 다뤘다. 로컬 서버 실행 권한, 악성 도구 출력과 프롬프트 인젝션을 모두 해결한 것으로 해석하지 않는다.
