# Safe Personal RSI — 에이전트 지시문 변경의 채택 기준

에이전트 지시문을 고쳐 정상 작업 성능이 좋아져도 승인 경계는 나빠질 수 있다. Safe Personal RSI는 모델 가중치와 런타임 코드를 고정하고, 지시문 후보의 안전성과 작업 성능을 함께 평가해 채택 여부를 정한다.

- **발행·수정일**: 2026-11-18 v1, 2026-11-20 v2.
- **수집·검증일**: 2026-11-24 KST.
- **검증 범위**: [논문 v2 본문 및 표 F.1](https://arxiv.org/html/2611.23651v2#A6) 정적 검토. 코드 실행·모델 호출·재현은 하지 않았다.

## 기준 버전과 고정 비교군

후보는 변경 시점의 **현재 채택본(부모 버전)**과 비교한다. 새로 생긴 위반과 두 버전에 공통인 위반을 모두 보며, 실패가 반복되면 변경 일부를 임시로 원복해 수정 위치를 좁힌다. 후보가 안전성 평가와 정상 작업 성능 조건을 통과하지 못하면 현재 버전을 유지한다. 이 평가가 런타임의 권한 강제를 대체하지는 않는다.

통제된 채택 실험에서 **Frozen**은 초기 변경 전 지시문이다. 아래 수정 확인 실험에서는 **수정 전 업데이트**, **수기 규칙을 붙인 업데이트**, **채택된 수정본**을 각각 고정했다. 표의 차이를 초기 Frozen 대비 개선으로 읽으면 안 된다.

## 표 F.1: 수정 확인 결과

| GPT-5.6 Luna 고정 비교군 | 위반 플래그 | 안전한 작업 완료 | 명시적 승인 대조군 성공 |
| --- | ---: | ---: | ---: |
| 수정 전 업데이트 | 9/84 | 78/87 | 3/3 |
| 수기 권한 규칙 | 0/84 | 87/87 | 3/3 |
| 채택된 수정본 | 0/84 | 87/87 | 3/3 |

비교군마다 위험 검증 사례 28개를 각 3회 실행했다(84회). 명시적으로 승인된 정상 작업 사례는 **1개**를 3회 반복했다. 안전한 완료는 전체 87회 중 정상 실행·정당한 작업 처리·위반 플래그 없음이 모두 충족된 경우다. 수기 규칙도 같은 결과를 냈으므로, 이 비교만으로 자동 수정이 더 낫다고 볼 수 없다.

위험 사례 중 13개(39회)는 수정·채택 루프 밖에 있었지만 벤치마크 개발 단계에서 알려졌고 탐색에 재사용됐다. 독립 홀드아웃이 아니며, 반복 횟수는 새로운 사례 수가 아니다. 실험은 실제 모델을 썼지만 합성 계정과 모의 서비스를 사용했고 외부 전송과 거래는 막았다. 운영 중 실제 전송이나 권한 강제의 검증은 아니다.

## 작은 실험 제안

자율성을 높이는 지시문을 검토할 때, 합성 요청과 모의 발송 도구에서 현재 채택본, 수기 권한 규칙을 붙인 버전, 새 후보를 같은 조건에서 비교한다. 같은 캘린더 초안에 대해 명시적 승인이 있는 경우와 없는 경우를 짝지어 여러 과제를 구성한다. 승인 없는 변경의 차단, 승인된 요청의 정확히 한 번 실행, 모의 발송 영수증과 완료 보고의 일치를 별도로 확인한다. 수정에 쓰지 않은 독립 사례를 최종 평가에만 사용한다. 사전 지정한 위반이 발생하거나 정상 작업이 퇴행하면 현재 버전을 유지한다. 이 실험은 제안이며 실행하지 않았다.
