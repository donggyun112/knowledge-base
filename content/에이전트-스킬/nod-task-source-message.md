# Nod — 동시에 들어온 요청을 각 작업에 묶기

한 채팅에서 여러 작업이 동시에 진행될 때는 작업을 나누는 것만으로 충분하지 않다. **각 작업이 어떤 요청을 처리하는지**도 저장해야 한다. Nod의 공개 재현에서는 1.5초 간격으로 조사와 짐 목록을 요청했더니 짐 목록이 두 번 나왔고, 조사는 수행되지 않았는데도 카드에 완료로 표시됐다.

- **공개 시점**: 2026-11-22, [Nod v0.9.2 릴리스](https://github.com/n8n-io/nod/releases/tag/nod-v0.9.2).
- **수집·검증일**: 2026-11-25 KST.
- **검증 범위**: 공개 릴리스, 병합 PR, 태그의 서버 코드와 테스트 정적 검토. 설치·재현·모델 호출은 하지 않았다.

## 최신 메시지를 자동으로 고르지 않는다

기존에는 실행 중인 채팅 턴에 새 메시지가 들어오면, 작업이 가장 최근 메시지에 묶일 수 있었다. [수정 PR #1347](https://github.com/n8n-io/nod/pull/1347)은 작업을 시작하거나 기존 작업에 답을 전달할 때 어떤 사용자 메시지를 처리하는지 명시하도록 했다. 턴이 사용자 메시지 하나만 받았다면 그 메시지를 기본값으로 삼을 수 있다. 여러 개를 받았다면 ID를 명시해야 하며, [서버는 해당 턴이 실제로 받은 ID만 허용한다](https://github.com/n8n-io/nod/blob/nod-v0.9.2/src/server/thread.ts#L2053-L2068). [웹·컴퓨터 조작이 필요한 일](https://github.com/n8n-io/nod/pull/1293)은 별도 작업 세션에서 진행하되 결과는 같은 채팅에 보인다.

이 검사는 ID가 현재 턴에 속하는지를 확인한다. 현재 턴에 속하는 여러 ID 중 모델이 의미상 옳은 것을 골랐는지까지 증명하지는 않는다.

## 타이밍을 재현하는 회귀 테스트

[테스트 PR #1348](https://github.com/n8n-io/nod/pull/1348)은 실제 서버·PostgreSQL·턴 워커·태스크 세션을 HTTP 경로로 구동하고, 모델 응답만 스크립트로 대체한다. 스크립트는 먼저 요청에 응답하고 작업 시작을 늦춰 메시지가 한 턴에 쌓이는 상황을 만든다. 작성자에 따르면 바로 작업부터 시작하는 초기 스크립트는 기존 버그를 잡지 못했다.

[태그에 포함된 테스트](https://github.com/n8n-io/nod/blob/nod-v0.9.2/tests/e2e.test.ts)는 요청별 작업 시작, 지정한 작업으로만 가는 수정, 작업 하나를 멈춰도 다른 작업은 계속되는 경우를 검사한다. 강제 종료 뒤에는 자동 재실행하지 않고, 중단을 알린 뒤 사용자가 계속하라고 답하는 흐름도 검사한다. 스크립트로 고정한 일정에서의 결과다. 모델이 항상 올바른 요청을 해석하거나 외부 변경이 장애 뒤에도 정확히 한 번 실행된다는 보장은 아니다.

## 작은 실험 제안

외부 연결 없이 `문서 A 요약`과 `문서 B 목차 추출`을 넣는다. 스크립트 모델이 작업 시작을 기다리는 동안 두 입력을 같은 턴에 넣고, 각 작업의 원본 메시지 ID와 모의 결과를 대조한다. 복수 메시지에서 ID를 생략하거나 현재 턴에 들어오지 않은 메시지 ID를 쓰면 거절되는지, B에 보낸 수정이나 중단이 A에 영향을 주지 않는지 확인한다. 카드의 완료 표시와 실제 처리한 요청을 별도로 검사한다. 이 실험은 제안이며 실행하지 않았다.
