# 기술 레이더 운영 기준

자료를 모으는 데서 끝내지 않고, 무엇을 읽고 어떤 조건에서 실험할지 기록한다. 기존 주제별 목차는 그대로 유지한다. 레이더의 영역과 단계는 각 자료에 덧붙이는 판단 기준이다.

[Thoughtworks Technology Radar](https://www.thoughtworks.com/radar/faq)의 분류 방식을 참고하되, 아래 단계는 이 지식베이스의 직접 검증을 기준으로 사용한다. 원 레이더의 추천이나 기술의 인기와 같은 의미가 아니다.

## 네 가지 영역

| 영역 | 분류하는 대상 |
| --- | --- |
| Techniques | 평가 방법, 메모리 설계, 복구 전략 등 구현체와 독립적인 기법 |
| Platforms | 실행 환경, 배포 기반, 격리 환경 |
| Tools | 개발·평가·운영에 사용하는 개별 도구 |
| Languages and frameworks | 언어, SDK, 런타임 프레임워크 |

주 영역 하나를 정하고 관련 분야는 태그로 보완한다. 영역별 항목 수를 맞추려고 자료를 추가하지 않는다.

## 채택 단계와 읽기 상태

| 단계 | 판단 기준 |
| --- | --- |
| Adopt | 명시한 요구와 운영 조건에서 직접 검증했고 적용 범위와 근거를 기록했다 |
| Trial | 범위를 정한 실험 또는 제한된 적용을 진행 중이며 성공 기준과 되돌리기 조건이 있다 |
| Assess | 조사하거나 실험 후보로 검토할 가치가 있지만 아직 적용 조건에서 검증하지 않았다 |
| Caution | 구체적인 위험이나 요구 충돌 때문에 신규 적용을 보류한다. 재검토 조건도 기록한다 |

새 자료는 기본적으로 **Assess**다. 읽기 상태는 **읽기 전 / 읽는 중 / 읽음 / 보류**로 별도 관리한다. 자료가 수집됐거나 요약이 있다는 이유로 사용자가 읽었다고 표시하지 않는다. 읽기 완료, 인기, 외부 벤치마크만으로 채택 단계를 올리지 않는다.

단계가 바뀌면 날짜, 적용 조건, 관찰 결과, 남은 위험과 판단 근거를 남긴다. 이전 결정과 사용자 메모는 지우지 않는다. Caution은 명시한 조건에 대한 보류 판단이다.

## 매일 수집할 때

1. 하루 최대 3건을 고른다. 새로운 발표뿐 아니라 미해결 질문을 설명하는 기존 핵심 자료도 포함한다. 적합한 자료가 없으면 추가하지 않는다.
2. 공식 문서, 원 논문, 명세, 작성 팀의 기술 글을 우선한다. 원문의 주장과 이 노트의 해석·실험 제안을 구분한다.
3. 기존 노트의 제목과 대표 URL을 함께 확인한다. 리디렉션과 추적 매개변수를 정리하고, 같은 자료의 개정은 기존 노트에 변경 내용을 추가한다.
4. 발행일과 수집일을 구분한다. 날짜가 없으면 미표기로 남긴다. 수집일은 KST 기준으로 기록한다.
5. 한국어 요약, 기술적 활용 맥락, 한계, 다음 질문, 읽기 상태와 채택 단계를 함께 남긴다. 측정하지 않은 효과와 점수는 쓰지 않는다.
6. 기존 주제 폴더에 저장하고 홈 목차를 갱신한다. 원시 대화, 인증 정보, 개인 업무 구상과 비공개 자료는 공개하지 않는다.
